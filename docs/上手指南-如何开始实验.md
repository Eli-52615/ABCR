---

## 0. 一句话:这套东西是什么

它**不是一个网页面板**,是一套**命令行 + 账本**。核心思想是:

> **账本先于叙事——无账本记录 = 没发生过。** 你看到的一切结论,都是账本上的查询结果;程序嘴上说什么不算数,账本里写了什么才算数。

所以没有花哨界面。你和它的交互,**一辈子只有三个动作**:

```
①  提计划草案   →   ②  你签字批准   →   ③  看账本 / 看审计结论
   (abcrctl draft)    (abcrctl approve)     (a_views / a_audit)
```

中间的执行(跑模型、评分、独立复评、异常检测)**机器自己干**,不用你管。你的签名只花在"改变证据性质"的地方,不花在每一次执行上。

## 2. 第一次上手:5 分钟跑通一个 fake 批(零成本)

### 第 1 步 —— 开工体检(必须全 PASS 才继续)

```bash
PYTHONPATH=src .venv312/bin/python scripts/preflight_kickoff.py
```

看到末行 **`== 结果:30/30 PASS ==`** 就对了。这是在确认:分支/环境/冻结数据/令牌签名等 30 项都健康。任何一项 FAIL 都别往下走,截图发我。

### 第 2 步 —— 用 fake 引擎跑一个完整批次

```bash
PY=/Users/superagent/shared-brain/ABCR/abcr/.venv312/bin/python bash scripts/run_r2_batch.sh fake
```

`fake` = 不调真模型、不花钱、不联网,用假引擎走完**整条链路**:签发信封 → 分发执行 → 评分 → 独立复评 → 审计 → 出复现包。这是"链路通不通"的自证。跑完你会看到一个 `batch_id`(形如 `B-20260720T...`)和每一步的 PASS/FAIL。

> 注:fake 批里 `item6 成本对账` 会显示 FAIL——这是**故意的**(fake 没有真 GPU 开销可对账),脚本会注明"其余项 PASS 即结构就绪"。别被这一条吓到。

### 第 3 步 —— 看账本

```bash
PYTHONPATH=src .venv312/bin/python scripts/a_views.py runs        # 看跑了哪些 run
PYTHONPATH=src .venv312/bin/python scripts/a_views.py anomalies   # 看有没有异常
PYTHONPATH=src .venv312/bin/python scripts/a_views.py scores      # 看评分
```

这三个命令**只读账本**,永远不会改任何东西,放心随便跑。

## 3. 真正开始一个实验:三个动作详解

### 动作① 提计划草案

你(或我帮你)先写一个实验规格(哪个 trait、哪些任务、几个 seed),然后:

```bash
scripts/abcrctl draft plans/specs/<你的实验>.json
```

它会调用规划器,生成一个**信封草案**(batch envelope)并做预检,把预算、范围、要跑什么都摆给你看。**这一步不执行任何东西**,只是把计划摊开。

### 动作② 你签字批准

看过草案没问题,签发:

```bash
scripts/abcrctl approve configs/envelopes/<信封id>.json --ttl-hours 24
```

**签发权物理上只在这个命令里**(全系统唯一能签令牌的地方)。签完,机器凭这个带时效的令牌去执行——它不能自己给自己发令牌。不想批就 `abcrctl reject ... --reason "..."`。

随时查状态:

```bash
scripts/abcrctl status
```

### 动作③ 看审计结论

执行跑完后,**独立的审计器**(验船师)会复评、对账、查污染,给出结论:

```bash
PYTHONPATH=src .venv312/bin/python scripts/a_audit.py <batch_id> --items 1,2,3,4,6
```

看 `overall=PASS` 还是 `FAIL`,以及每个 item(完整性/复评一致/防污染/版本一致/成本对账)的分项结论。

## 4. 为什么现在可以信任那些"绿勾"(这是这次加固的重点)

加固前,这套系统有个致命病:**什么都没干也报绿、被篡改也报绿**——你照着跑会拿到一堆假对勾。现在四道结构性防线补上了:

| 防线 | 通俗说 | 挡住什么 |
|---|---|---|
| **外部信任根** | 每条账本收口时在"仓库外部"盖一个带长度的印 | 有人偷偷删掉超支记录、或整本账重抄一遍洗成满分——都会因为"印对不上"被抓 |
| **空即失败** | "没有数据"绝不等于"满分通过" | 空运行、幽灵批次、删掉题库——不再静默报 PASS,一律 FAIL |
| **验船师只看不碰** | 审计器没有改账本的权力 | 审计器不能把自己刚查出的问题重新盖印成合规 |
| **判据真接线** | 文档里写的检查,代码里真的会执行 | "干预其实没生效""超支了却没熔断"这类"写了没做"的洞 |

**一句话:现在如果审计说 PASS,是因为真的验过了;说 FAIL,是真的有问题。** 绿勾恢复了含义。

## 5. fake 与真跑的边界(重要,别踩)

- **探索期(你现在)**:用 `fake` 引擎 + Mac,零成本。所有产物自动标记 `non_citable`(不可引用),因为 Mac 上的数不能当正式证据。**这个阶段随便跑,跑坏了也不花钱。**
- **真跑(以后)**:需要 24GB 云卡跑 bf16 才产 citable 证据。那要先租卡(云日),现在**云日 #2 已暂停**,所以暂时不碰真跑。
- **成本闸**:即使你误跑了会调付费 API 的测试,系统会在**执行前**拦下(除非你显式设 `APPROVE_COST=1`)。所以正常操作不会意外烧钱。
