## 三、W3 残留清单(确认期前必须处理)

> 这三条都不是"什么都没干也报绿"那一类(那类已全关)。它们要求**攻击者已握有相当权限、并精心构造特定制品**。探索期(Mac/¥0/无真卡)不触及;但 W4–5 确认期出版证据前必须闭合。

### R1 — 云单价自述(原 V13,fail-open 但需控制注册)
- **面**:`ops/cloud.py` 的 `metered = price_cny_per_h × elapsed` 交叉核对已挡住"谎报金额";但 `price_cny_per_h` 本身是 `register()` 时的自述值,零校验。谎报**单价**(报 0 或极低)→ metered 算出 ¥0 → 与自述金额吻合,真实烧卡被洗成合规。
- **修法**:`cloud.register()` 校验单价(正值 + 按厂商/机型价格下限);单价也纳入外部锚。
- **触发前提**:能控制实例注册入参。探索期无真卡,不触及。

### R2 — 成本闸无网络出口管控(原 V17,纵深不足)
- **面**:`tests/conftest.py` 的成本闸已在 collection 前按文件名/marker 拦下已知付费用例(A1–A3 实测拦下,打印 `cost-gate: armed`)。但它**不是 syscall 级**:一个不匹配命名模式的新付费测试、或直接开 socket 的代码,不被拦。
- **修法**:conftest 增加网络出口守卫(socket 层阻断 + 白名单),把"按名字拦"升级为"按行为拦"。
- **触发前提**:新增一个不落命名规则的付费测试。当前已知付费用例已被拦。

### R3 — pack 验证器 sys.path 影子模块(原 V04,fail-open 但需构造 pack)
- **面**:字节码影子(.pyc)向量已关(DENY 后缀 + hash 校验)。但 `rescore_standalone` 把 `pack/tools` 置于 `sys.path[0]`,验证器自身的 import 可被劫持:**声明**一个纯源码的、与验证器所 import 的某个 stdlib 模块同名的影子,即在清单内、绕过 .pyc 拦截。
- **修法**:验证器在隔离解释器/干净 sys.path 下运行,或不把 pack 的 `tools/` 前置进 sys.path。
- **触发前提**:能构造一个申报了 stdlib 同名影子模块的复现包。

### 更深层观察(已记录,更弱前提之上,非当前 fail-open)
- `review` 的 `non_citable` 逃逸:攻击者置 `manifest.non_citable=true` 可走宽松路径——但这样产物本身即不可引用,无法充当 citable 证据。
- `guarded_reseal` 的 `repo_root`/`led.path` 解析重定向:需攻击者控制账本目录解析(D-redirect 形态)。

## 五、审计方法学备注(供后续加固复用)

1. **修复方必须独立于复验方**。三轮每条都由"假设修复在撒谎"的独立 agent 真跑击穿 + 阴性对照证明检出力。5 轮手工修复曾栽在自证。
2. **"BYPASSED 清零"不是终极闸门**。对抗验证是分形的——只要指示复验者"换等价攻击再试",总能找到更深一层。正确判据是:**fail-open 类彻底关闭 + 残留需超出当前阶段威胁模型**。第三轮据此把验证改为收敛式(只判指定残留 + fail-open 回退,更深层记为观察)。
3. **并行化的隔离边界会变成正确性断点**。第一轮按文件硬切所有权,切断了"扩展定义"与"使用定义"之间的接线(treehash/dispatch 分叉、seal_chain 无调用点)——制造出的正是本项目要修的病(判据没接线)。第二/三轮改为按"修一条 bug 的完整闭包"分组。
4. **"接线"与"越权"只隔一层**。为让机制被调用而随手加调用点,可能把权力加到不该有的角色上(auditor 获写锚权)。正确接线是"生产者封印一次、验船师只读只验"。
