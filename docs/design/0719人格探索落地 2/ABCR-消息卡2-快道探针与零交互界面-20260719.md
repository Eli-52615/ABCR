## A. 快道探针（probe）——楠的小时级学习环

**目标一句话**：楠一条命令（或一句飞书）就能在本机测 1–3 个人格变体，半小时级出对照表，除"写一行预测"外零纪律、零审批、零云、零账本。

1. **入口**：CLI `probe` + 飞书指令两种触发，参数：人格（临时文本或注册表 id；临时文本自动存 `snippets/` 带哈希）、题集 tag、题数 n（默认 20）、seed（默认 1 个）、开关 `--with-3L`、`--arm vanilla`（默认恒带）。
2. **唯一纪律**：`--predict "<一行预测>"` 为必填，缺则拒跑并提示。这是全系统对楠唯一的强制输入。
3. **引擎**：行为主档 = Qwen2.5-7B-Instruct 4bit 本机（llama.cpp / MLX / Ollama 三选一，选定后**冻结实现与量化档并记版本**——量化档漂移会污染 notebook 纵向可比性）；练习档 = 3B fp16 MPS（走既有 transformers+hook 路径，可看投影，输出一律标 non-conclusive）。
4. **判分**：复用 deterministic checkers（IFEval 族现成）；judge 默认关（省时省钱），行为学指标（长度、hedging 率、自检标记率，constants 冻结词表）照常计算。
5. **输出**：终端/飞书即时表——各变体 vs vanilla（vs ③ᴸ 若开）的分差与指标差；同时 append-only 写 `lab-notebook.jsonl` 一条：ts、persona 哈希与指针、items、seeds、engine+quant 版本、scores、prediction 原文、结果摘要一行。notebook 是楠的私有学习档案，**永不对外引用**（G7），面板只读展示并标"学习数据 · 不可引用"。
6. **题池规则**：探针只从 dev 池随机抽；**毕业批（证据道）换用与近期探针不相交的新抽 dev 子集**（编译器负责取差集）；cal/holdout 对快道结构性不可达（路径级隔离，与卡 #1 §3-6 同一机制）。
7. **毕业机制**：`probe promote <notebook行id>` → 自动把该行转写为目标书草稿的假设字段（persona 指针、预测方向、探针证据摘要），进卡 #1 的证据道流程。
8. **周校准**：每次云窗自动附带"快慢一致性检"——重跑最近 N 条（默认 10）探针的子集于 7B bf16，产 4bit↔bf16 方向一致率与分差小表，入轮报告；一致率低于阈值（占位 0.8，楠可改）时面板黄牌提示"本地信号降权"。
9. **延迟目标**：3 变体 × 20 题 × 1 seed 本机 ≤ 40 分钟（含 vanilla 臂）。达不到则如实报告瓶颈与实测数，不许静默缩题量。

## B. 审批桥——楠打字批准，人域代理签发

1. 云批的审批请求以**飞书卡片**送达楠：planner 摘要（批次意图、人格清单、题量、split、预算估算、异常标注）+ 批准/拒绝按钮（或文字"批准 <batch_id>"）。
2. 签发动作由**人域签批代理**执行：常驻进程，独占签发密钥，只认楠的飞书身份（uid 白名单）；**系统执行域（Operator/dispatch/planner）照旧无钥**——"系统不能自批"的骨架不动，动的只是人的输入形态。
3. 诚实边界入文档：信任边界从"人亲手跑命令"移到"人的一条消息 + 人域代理"，新增残余风险 = 飞书消息伪造 / 代理进程被攻，单机威胁模型下接受；abcrctl 保留为后备与例外通道。
4. 批准、拒绝、超时（默认 24h 过期）全部入账本；代理自身的启停与密钥轮换记录入账本。

## C. 工程任务派发自动化——楠与 Code 零接触

1. 建 ABCR mission 收件箱，复用 OC 既有"指令自动落箱 + 常驻消费"模式：消息卡落箱 → 管家进程拉起并行 Code 窗执行 → Execution Report 回写 → 面板展示。
2. 楠的动作 = 0 或一条飞书"执行 <卡名>"；涉及费用或危险面（动契约冻结区、动云）的卡走审批桥确认后再执行。
3. 管家对执行失败的处理沿既有纪律：如实报告 + 决策包上呈，不静默重试到绿。

## D. 面板——楠的唯一阅读界面

五段：待审批 / 在跑（心跳与进度）/ 轮报告就绪 / 异常分诊 / 预算水位；外加快道 notebook 只读视图（标注"学习数据 · 不可引用"）。飞书文档自动更新为主、本地页为辅；每项带下钻链接接 C1-7 三层钻取。轮报告就绪与异常触发飞书通知（notify.py 接线，按类冷却沿 §7.1）。

## 约束

1. 快道与账本体系互不相通（本卡开头修订②）；签批代理与快道互不相通。
2. 快道引擎、量化档、题池抽样种子全部入 notebook 行，保证任意一针可复跑。
3. LLM 仍只允许出现在报告/转写位置（卡 #1 §3-3 不变）；审批桥、派发、探针判分全部零 LLM。
4. 新增账本事件词（审批桥、派发类）走契约修订广播流程。

## 验收

1. probe 端到端真跑一次：本机 7B 4bit，2 个占位人格变体 + vanilla，40 分钟内出表，notebook 落行；缺 `--predict` 拒跑实测。
2. `probe promote` 产出合法目标书草稿段并通过卡 #1 校验器。
3. 审批桥真链一次（fixture 批）：飞书卡片 → 批准 → 代理签发 → dispatch 消费；拒绝与超时路径实测。
4. 收件箱→管家→Code→回报全链演练一次（用一张无害测试卡）。
5. 面板五段 + notebook 视图渲染；黄牌逻辑用人造低一致率数据触发一次。
6. 快慢一致性检脚本就位（真云跑挂到下一个云窗执行）。
