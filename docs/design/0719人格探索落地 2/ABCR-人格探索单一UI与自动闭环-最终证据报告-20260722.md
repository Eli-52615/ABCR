## 4. 方案 §16 的五个最终问题

**没有。** Mac mini 尚无 ABCR sealed active release、`/usr/local/libexec/abcr-launch`、完整 `ABCR-Work` 或已加载的 12 个 launchd 服务。

终态唯一入口是**独立 ABCR 飞书研究驾驶舱**。现在尚未完成事件 owner receipt 与部署 E2E，所以还不能对人宣称这个入口可用；当前只能使用受审 offline CLI 和本地只读面板作工程验收，不能把它们当作终态日常入口。

### 4.4 哪些故障能自动处理？

代码与 fixture 已证明：重复事件幂等、lease 过期重排、毒丸单任务隔离、中途 kill 后无重复恢复、已知故障有界退避、证据风险隔离不修绿、未知代码故障只生成一条 mission、坏候选不发布及 active CAS 回滚。部署前这些仍是 CODE_RC 能力，不是线上 SLO 证明。

## 6. AUTONOMOUS_QUAL 在哪一步完成

`AUTONOMOUS_QUAL` 不是提交代码或跑单测时完成，而是在 **reviewed runtime 获独立签名并经 root genesis 部署之后**，按顺序完成以下现场演练时才成立：

1. 12 服务真实语义健康 + 飞书 E2E；
2. Mac 整机重启后消息、outbox、runstate、lease 和幂等恢复；
3. 一个无害真实缺陷经受控 Codex adapter 修复、外部测试、verifier、canary、release；
4. 一个故意坏补丁被拒绝，active 不变或成功回滚；
5. 坏 bootstrap/broker slot 被 selector 拒绝；
6. 云 bf16、费用和 4bit↔bf16 校准完成。

当前缺生产 verifier 权限、root 安装动作、真实 Codex/egress 资格和可安排的重启/云窗口，Codex 不能在不越权的情况下自行把这一层改成 PASS。
