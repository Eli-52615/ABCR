# ABCR 人格探索：傻瓜级使用手册

> 这份手册只讲你怎么用，不要求你懂代码。  
> 代码合进 `main` 不等于已装到 Mac mini。管理员完成独立签名、root 安装和飞书真人验收前，机器人仍不能作为正式入口使用。

## 1. 每天只找一个入口

日常只在飞书里与 **ABCR 机器人一对一私聊**。不要开代码窗口，不要 SSH，不要手改 JSON，也不要把私钥、密码、token 或整段日志发给机器人。

先发：

```text
帮助
```

再发：

```text
状态
```

`状态` 会汇报：待确认目标、快道、正式实验、审批、报告与草稿、异常。它会明确写“需要你：是/否”。若写 `UNKNOWN`，意思是证据不足，不是零成本或已经成功。

## 2. 部署并通过真人一题验收后可用：分段快道

快道只用于学习方向，永远是“学习数据·不可引用”。设计上只运行不带③L的本机
Qwen2.5 快道；系统不会下载模型，也不会拿 Qwen3、云模型或本机结果冒充正式证据。
管理员尚未完成第 7 节真人一题闭环前，它的准确状态是“待资格化”，不能称为“真正可用”。

第一步，发：

```text
开始快道
```

机器人返回 `PS-...`。把下面的会话号换成它给你的完整值：

```text
快道片段 PS-... 1/1
预测：该人格会提高找错类任务表现，但不会只增加输出长度
人格文本：在回答中持续检查冲突与遗漏，但不改变事实标准
题量：20
种子：1
带③L：否
模型档：qwen25-7b-q4-v1
```

最后发：

```text
结束快道
```

系统会依次回复“安全入箱”“题集已封印/实验排队”“快道完成”。中途想看进度只发 `状态`。
设计要求断线或重启后重放同一事件只能恢复原动作，不重复造实验；部署验收必须用事件、
session/hash 和唯一 probe 证据实测，不能只凭这句话判 PASS。

完成后按机器人给出的 `probe_id` 发：

```text
查看快道结果 PROBE-... 1
```

每行都有完整 `row_hash`。想把某一行带回你和 Claude 的理论讨论，复制：

```text
毕业这一针 <完整64位row_hash>
```

它只生成待你和 Claude 审阅的草稿，绝不会自动启动正式实验。

`先做快道 G-...` 只有机器人主动给出“已可信编译”的完整 G 卡时才能用；当前正式执行档
未资格化，普通使用者不要自行拼 G ID。日常只走上面的 `开始快道` 分段表单。

## 3. 提交你和 Claude 已定稿的目标书

依次发送：

```text
开始提交目标书
```

```text
目标书片段 PS-... 1/1
<粘贴你和 Claude 已定稿的完整目标书 YAML>
```

```text
结束提交目标书
```

机器人返回 `PROP-...` 后，核对无误再发：

```text
确认目标 PROP-...
```

目标书很长时可分成 `1/3`、`2/3`、`3/3`，编号必须连续，总片数不能中途改变。遇到缺字段、重复 key、越界题集或不支持的模型档，请回到 Claude 修改，不要让管理员绕过。

确认后，后台会自动做选题、冻结、编译、审批、执行、审计、复算和报告投影。当前正式远程 CUDA 执行档尚未受审，正式链会在安全门前停住；这不是卡死，也不能通过下载模型或创建云主机解决。

## 4. 审批只复制最后一张卡

批准和拒绝必须完整照抄，例如：

```text
批准 APR-... abc123def456 v2
```

```text
拒绝 APR-... abc123def456 v2：预算过高，先缩小题量
```

只复制版本最大的最新卡。卡片过期后，系统会生成同一请求的 `v+1` 续签卡，旧卡永久失效。
重复发送同一批准最多生效一次。费用和 ETA 没有新鲜校准时，卡片必须明确显示
`预计费用：UNKNOWN；预计时长：UNKNOWN`；`费用上限` 只是不能突破的 cap，不是预计费用。

正式云目前固定禁止：不要创建实例、不要启动、不要充值、不要登记云地址。未来只有独立审查并安装远程 CUDA 适配器、价格档和云专项续签后才会开放。

## 5. 查看正式报告、草稿并形成下一轮

只有报告完成 Auditor 验签、独立复算并与终态 workflow 绑定后才会返回内容：

```text
查看报告 ROUND-...
```

报告把“已签名证据摘要”和“未由 Auditor 担保的机器解释”分开显示。逐题下钻：

```text
下钻 ROUND-... ifeval_zh_v1 item-...
```

查看惰性草稿：

```text
查看草稿 DRAFT-...
```

草稿固定是 `draft_only=true`、`auto_execute=false`。把它交给 Claude 讨论，形成新的完整目标书，再按第 3 节提交。系统不会自己修改理论目标或自动开下一轮。

记录反思：

```text
记录反思 ROUND-... 我认为差异更可能来自题型；下一轮应换未见题并固定主指标。
```

长反思可用：`开始记录反思 ROUND-...` → `反思片段 PS-... 1/1` → `结束记录反思`。

## 6. 卡住时只做三步

1. 发 `状态`。
2. 对隔离或停止对象发 `为什么停了 <对象ID>`。
3. 只把“错误代码、对象 ID、发生时间”交给管理员；不要发 secret，不要自己改文件。

只有机器人明确给出可恢复对象时，才复制 `暂停 <对象ID>`、`恢复 <对象ID>` 或 `中止 <对象ID>`。

`BLOCKED` 通常表示外部资格尚缺，不等于后台死机。正式 experiment execution profile/CUDA、
生产云、带③L快道、高风险任务自动批准、真实 Codex 自修复和整机重启演练目前都必须保持
`BLOCKED`，直到各自完成独立资格化。不要 pip/uv/brew 安装依赖，不要下载/转换模型或重装
Ollama，也不要手写 profile；这些都不能解除正式门。

## 7. 管理员部署后，你只做一次验收

1. 私聊发送 `帮助`，确认收到有限命令清单。
2. 发送 `状态`，确认状态新鲜，不是只显示进程存活。
3. 跑 1 题、不带③L的快道；验收表单固定写 `题量：1`、`种子：1`、`带③L：否`、
   `模型档：qwen25-7b-q4-v1`。
4. 票据必须同时有同一 session/request hash、唯一 `itempool_queued`、唯一 `probe_queued`、
   `probe_completed`、`result_hash`、唯一 `row_hash`，且 `查看快道结果 PROBE-... 1` 返回同一行。
5. 重发原 `结束快道`，确认复读同一对象且没有第二个 probe；结果必须写“学习数据·不可引用”。
6. 发一个错误版本/错误指纹的批准，确认被拒绝；再用最新卡正确批准。
7. 管理员严格按权威 runbook §10.1 的 bootout→bootstrap→semantic doctor 顺序重启
   human-gateway；重启后发 `状态`，并另用 Feishu redelivery/outbox 证据验证旧回复可恢复。

这些都通过后，才把飞书机器人当成日常唯一入口。管理员权威步骤见仓库
`ops/install/REVIEWED-RUNTIME-INSTALL.md`；不要从 dirty checkout 直接安装，不要使用临时
verifier 私钥，也不要让一次性 owner 发现器与 Human gateway 同时保持长连接。

## 8. 一页速查

```text
帮助：帮助
全局：状态
预算：预算
快道：开始快道 → 快道片段 PS-... 1/1 → 结束快道
结果：查看快道结果 PROBE-... 1
毕业：毕业这一针 <64位row_hash>
目标：开始提交目标书 → 目标书片段 PS-... 1/1 → 结束提交目标书 → 确认目标 PROP-...
审批：批准 APR-... <指纹> vN
拒绝：拒绝 APR-... <指纹> vN：原因
报告：查看报告 ROUND-...
草稿：查看草稿 DRAFT-...
反思：记录反思 ROUND-... <文字>
停因：为什么停了 <对象ID>
云：当前禁止创建、启动、充值或登记
```
