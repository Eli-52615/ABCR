## 2. 处置:判定核心从 fail-open 翻转为 fail-closed

**commit `600e95f`**,重写 `scripts/check_runbook_refs.py` 判定核心为四层:

```
Layer 0  文档分段   markdown 围栏 + 4 空格缩进块;
                    非 shell fence 用**黑名单**排除(白名单会让 ```text 整块失明,
                    真实 runbook 用了它 37 次);
                    console/sh-session fence 只取提示符行(其余是程序输出)
Layer 1  真分词     shlex(posix=True) 逐行分词 —— 一步消掉全部引号形态;
                    分词失败 → 盲区,不放行
Layer 2  符号求值   变量赋值 / 别名链到不动点 / for 多值 / 参数展开修饰符 /
                    规范化命令替换;登记表语义优先于赋值字面值
Layer 3  裁决       仓库存在性 × 封印清单;**看不懂的一律 [解析器盲区] 阻断**
```

`sealed` 由此成为「求值出的根」的属性,而不是「周围 60 字符」的属性。

**这是结构性修复而非补丁的判据**:新的绕过形态**不能**保持静默,只会变成响亮
的盲区告警。作者/攻击者的可乘之机,从「解析器**不懂**的东西」(表面积无穷、
不可枚举)缩小到「解析器**懂错**的东西」(可枚举、可测试、可对着 POSIX 规范审查)。

### 2.1 顺带修正的两处认知错误

- **封印树 ≠ git allowlist**。`env/bin/python`、`trust/review-verifier-attestation.pub`
  确实不在 git 里,但确实在封印树里。清单改为
  `git allowlist ∪ builder 派生产物`,且从 `build_reviewed_runtime.py`
  **解析**而非手抄(有元测试:篡改 builder 常量后清单必须随之变化)。
  曾有审查视角提议把 `env|trust` 塞进路径正则白名单 —— 那是错的方向,
  实测会在权威 runbook 上立刻产生新误报。
- **中文文件名截断**。枚举式字符类把
  `scripts/cloud/R2-操作说明-非技术人员照抄版.md` 截成 `scripts/cloud/R2-`,
  再报一条「文件不存在」的**假**幻影引用。守门器自己制造噪音是最坏的失败模式,
  改为排除式字符类。

### R1 — markdown 作用域根未实现(静默,中)

表格「执行根」列 + 「脚本」列、标题挂目录 + 列表裸文件名、
「下列脚本均位于 X 之下」+ 编号列表 —— 这类**根与路径分处不同 markdown 结构**
的写法,sealed 判定会漏(判成 False)。

**缓解**:幻影引用通道**仍然覆盖**(路径本身会被抓到并核对存在性),
即轮 2 P0 那类事故仍挡得住;漏的只是封印遗漏判定。
**未做的理由**:markdown 结构的根推断是启发式,硬拦会踩误判,
独立评审亦建议这一层全部降级为 WARN。

### R2 — 安装后绝对路径不映射回仓库(静默,中低)

`/usr/local/libexec/abcr-bootstrap-selector` 这类安装后路径落在 `SYSTEM_PREFIXES`
内被忽略,不会映射回 `scripts/abcr-bootstrap-selector` 做封印检查。
**未做的理由**:需要解析 `install_abcr_runtime.py` 的目标表,且 `/usr/` 下绝大
多数路径(`/usr/bin/shasum` 等)确实与本仓无关,全查会噪音爆炸。

### R3 — 命令替换白名单是白名单(响亮,中)

只有 `realpath/readlink/echo/printf/dirname/pwd` 透明求值,其余命令替换一律
盲区阻断。方向是 fail-closed,但代价是:真实 runbook 若出现
`ROOT="$(jq -r .path x.json)"` 会被硬拦,须逐条登记进 `UNRESOLVED_WAIVERS`
并写明理由。**不得放宽名单**。目前三份 runbook 上该表为空。

### R4 — 根种子集仍是人工名单(响亮,中低)

`SEALED_ROOT_VARS` 与 `SEALED_ROOT_LITERALS` 是人写的。将来若引入第五个封印根
变量或更换 release 落地目录而忘了登记,该根下的路径会走 `UNKNOWN_ABS` 判定 ——
含 `/scripts/` 或 `/src/abcr/` 特征分量时**响亮报盲区**,否则静默。

### R5 — 只校验存在性,不校验语义(设计边界)

它只回答「这个文件存在吗 / 在封印树里吗」,**不**回答「这一步顺序对吗 /
这个脚本真的支持 `--seal-genesis-verification` 吗」。轮 2 P0 的另一半
(runbook "written for a different build")可以表现为「文件存在但 CLI flag 不存在」,
本守门器照样静默。**建议后续单独立项**:对封印脚本做 argparse 静态提取,
校验 runbook 用到的 flag 存在。不要塞进本次改动。

### R6 — 仓外 1014 行部署权威仍在 git 与封印树之外(治理,高)

本轮 P2 与前轮 3 条 P1 全部由它产生。它是「部署权威」却不受版本控制、
不进封印树、不在 CI 断言范围内(需显式传路径才检查)。
票据 `REL-3e8c1d1a` §5 该未决项至今未闭合。**建议收编进仓**。
