### 校验-3 为什么第 1 条最要紧(请 codex 记住这条判据)

方案 §4 自己写了约束「**无新 runtime 依赖**」,而把文件放进 `src/abcr/` 恰恰违反了它——
**不是因为引入了第三方库,而是因为 `src/abcr/**` 会被 builder 收进 runtime**。

这条容易漏判,因为它不需要任何人执行 `finalize`:
**文件位置决定是否进封印树,与是否执行发布动作无关。**
§5 写的「不做 release/finalize」管的是*动作*,挡不住*位置*带来的污染。

后果是具体的:`runtime_tree_hash = 46adc351…` 自 `85a1561` 起**六版未变**,
是 codex 此刻正在签署的 V5 attestation 的核心证据之一。快道若落在 `src/abcr/`,
这条基线当场作废,V5 需要重验。

**可复用的判据**:给这个仓库新增任何文件前,先问一句
「它在不在 `GIT_EXACT` / `GIT_PREFIXES` 里?」——
`python3 -c "import sys;sys.path.insert(0,'scripts');import check_runbook_refs as C;e,p=C._sealed_allowlist();print(C._in_sealed_tree('你的/路径.py',e,p))"`

## 1. 只做什么

做一个**本机单用户快道页面**，复用现有真实 Qwen 探针核心，补齐四件事：

1. 输入假设和人格文本；
2. 一键运行 `vanilla + 1 个人格`；
3. 查看汇总和逐题原始结果；
4. 复制上一轮，修改假设或人格文本，再开一轮。

默认固定：

```text
模型：qwen2.5:7b / qwen25-7b-q4-v1
题集：ifeval_zh_v1 的 dev
题量：1–20，默认 20
seed：默认 1
实验臂：vanilla + 1 persona
③L：关闭
judge：关闭
结果性质：学习数据 · 不可引用
```

## 2. 做完时，人怎么用

每天只有一个入口：运行一条固定命令，自动打开本机浏览器页面。若 Claude Code 判断双击 `.command` 文件更省事，可以同时提供，但不为此做 macOS App、安装器或服务。

页面只有三块：

### 新实验

- 本轮假设/预测：必填；
- 人格文本：必填；
- 题量：1–20；
- seed：默认 1；
- “开始实验”按钮。

系统自动带 vanilla。模型、量化档、题集和③L不让人在页面临时改，避免实验之间漂移。

### 结果

必须能看到：

- vanilla 与 persona 的通过率和差值；
- 输出长度、hedging、自检标记等现有确定性指标；
- 每一道题的题目、两臂原始输出、判分和 row hash；
- 实际模型指纹、seed、题量、耗时；
- 永久醒目的“学习数据 · 不可引用”。

系统只展示观察结果，不自动判断人格理论成立或失败。

### 再做一轮

点击“基于本轮新建”后：

- 预填上一轮的假设、人格文本、题量和 seed；
- 人修改后才运行；
- 产生新的 `probe_id`；
- 新轮记录 `parent_probe_id`；
- 旧轮内容和 hash 不变，仍可查看。

## 8. Token 使用：约 5:1，不做数字表演

目标是 Codex : Claude Code **大约 5 : 1**，允许正常浮动，不设精确闸门，也不为凑比例浪费 token。

这样分工：

- Claude Code只读一次完整任务卡，用主要精力集中实现和作者测试；不参与重复的方案讨论和多轮背景同步。
- Codex承担需求收敛、边界检查、独立审查、攻击测试、真实环境验证、缺陷票据和最终签名，因此自然使用更多 token。
- 一个实现 session + 一次窄交付；一个缺陷包 + 一次修复，避免来回碎片化沟通。
- 大致记录双方任务级 token 即可；明显偏离时解释原因，不做跨厂 tokenizer/cache 的精密换算。

最重要的不是数学上刚好 `5.000`，而是：Claude Code的 token 用在它最强的实现上；Codex的 token 用在提前消歧和独立验证上；双方不重复写代码、不重复熟悉整段历史。
