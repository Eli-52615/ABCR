## V4 修的入口缺陷

**现象**（真实主机、人工验收）：

```text
$ ./lab/fastlane/start-fastlane.command
...
  File "lab/fastlane/web.py", line 689, in serve
    httpd = ThreadingHTTPServer((host, port), FastlaneHandler)
OSError: [Errno 48] Address already in use
```

**根因**：无参数入口固定绑 `127.0.0.1:8787`，而该端口由长期运行、不得关闭的
AILH BOSS 控制台占用：

```text
$ lsof -nP -iTCP:8787 -sTCP:LISTEN
Python  32527 superagent  3u  IPv4 ... TCP 127.0.0.1:8787 (LISTEN)
$ ps -p 32527 -o lstart,command
Sat Jul 18 08:13:15 2026   …/V2/boss_console/boss_console.py
$ lsof -nP -iTCP:8788 -sTCP:LISTEN
bun     88701 superagent  6u  IPv4 ... TCP 127.0.0.1:8788 (LISTEN)
```

8788 也被别的服务占着，所以换一个相邻固定端口同样不可靠。

**闭合方式 —— 默认端口与显式端口是两回事**：

- `DEFAULT_PORT` 只是"没说的时候用哪个"的**起点**，快道对用哪个端口没有要求。
  无参数入口（Finder 双击同路）被占时**让位**到系统分配的空闲端口，
  并按**实际绑到的**端口打印 URL、打开浏览器——让位后还打印 8787，
  等于把人送到别人家门口。
- `--port 8787` 是人**明确表达的意图**，被占时当场报 `port_in_use` 并停止，
  **不替他换**：悄悄换到别处会让人对着错误地址干等，"帮倒忙"比"没帮上"更难查。

`web.bind_server(host, port, *, fallback_to_ephemeral=False)` 成为**唯一**绑定入口，
回环边界也收在里面（这样没有哪条路径能绕开它）。只有 `EADDRINUSE` 才让位；
其他 `OSError` 归一成 `port_unavailable`，不再以裸 traceback 收场。
CLI `--port` 缺省改为 `None`，`cmd_serve` 据此分辨"人没说端口"与"人正好指定 8787"。

**V4 实测（BOSS 仍占着 8787，未杀任何进程）**：


**错在哪**：身份闸只长在 `_dev_bundle()` 上，而三条提交路径

那一轮**恰恰是在这份坏 split 下产出的**：`request_fingerprint` 吃进 `split_sha256`，

旧轮是历史事实，可读性不该取决于今天的冻结件长什么样，否则数据一坏，
连"回去看当初到底跑了什么"都做不到，而那正是查清问题需要的。

### B2 Important · 单条结构非法但 JSON 合法的 round 拖垮整个历史

**错在哪**：`_load_record()` 假定顶层是 dict。

**V2 10f4397 实测**（真服务、真 curl）：

```text
round 内容 []          首页 http=500  首页列出 0/3 条轮次   错误页里是裸 AttributeError
                       （'list' object has no attribute 'get'，穿过只接
                         FastlaneError/OSError 的 scan_rounds 直达兜底页）
round 内容 {}          首页 http=500  首页列出 0/3         裸 KeyError: 'probe_id'
round 内容 {probe_id}  首页 http=200  但坏轮**冒充正常轮**进入列表，
                       点开详情才炸 KeyError: 'bundle_id'
三种形状的坏轮详情      http=500，均不含任何稳定错误码
```

**闭合方式**：`_load_record()` 把一切结构异常归一成带**稳定错误码**的 `FastlaneError`：

| 形状 | 错误码 |
|---|---|
| 顶层不是对象（`[]`、`"…"`） | `round_malformed` |
| 缺必需字段（`{}`、只有 `probe_id`、缺 `record_hash`/`bundle_id`） | `round_incomplete` |
| 必需字段类型不对（`count="1"`、`row_hashes="abc"`） | `round_malformed` |
| 文件名与记录里的 `probe_id` 不符 | `round_id_mismatch` |
| `record_hash` 复算对不上 | `round_tampered` |
| JSON 解析失败 / 读盘失败 / 兜底 | `round_unreadable` |

`record_hash` 进入必需字段：旧版走的是"没写就不查"，那是一条把 fail-closed
自己消解掉的出口——验不了就是不可信，不是默认可信。
`scan_rounds()` 另加兜底捕获，保证**一条文件写坏绝不让整段历史不可见**；
兜底同样落成一条可见的带码失败，并带上异常类型便于查。

**V3 实测**（真服务、真 curl）：

```text
round 内容 []          首页 http=200  首页列出 3/3   坏轮在首页=True  坏轮详情 500 带稳定码
round 内容 {}          首页 http=200  首页列出 3/3   坏轮在首页=True  坏轮详情 500 带稳定码
round 内容 {probe_id}  首页 http=200  首页列出 3/3   坏轮在首页=True  坏轮详情 500 带稳定码

```

**未误伤真实记录**：仓内真实 `lab/runs/` 的 5 条历史轮次在严格化后
`scan_rounds()` 得到 **5 条可读 / 0 条读不出来**，`check` rc=0。

## V2 闭合的四项（`10f4397`，保留记录；这四项本身在 V3 中未回退）

### 一（阻断）· family 漂移把 holdout 当 dev — `lab/fastlane/split_adapter.py`

**V1 的错在哪**：三道闸最硬的一道用 `assign_split(family, item_id)` 逐条复算，
而判据 `family` **读自那份不可信文件本身**——等于用锁自己的钥匙验锁。

**在 `eeae494` 树上实测复现**（把 V2 的伪造脚本放到 V1 树跑）：

```text
真实 split: family=ifeval_zh_v1 dev=42
伪造 split 三道闸: ACCEPTED  family=not-ifeval counts={'calibration': 95, 'dev': 47, 'holdout': 108}
被偷渡进 dev 的非 dev 题: 40 条, 样例 ['ifzh-0003','ifzh-0005','ifzh-0008','ifzh-0016','ifzh-0019']
其中原本是 holdout 的: 25 条
```

**闭合方式**：判据全部钉在**仓内权威坐标**上（都不受被校验文件影响）：

| 坐标 | 权威来源 |
|---|---|
| family | `FROZEN_FAMILY = "ifeval_zh_v1"` 代码常量（`08` §1 固定题集） |
| salt | `abcr.rig.splits.SALT` —— **协议常量**，在 `src/` 里 |
| split 身份 | 冻结路径 + 字节 `sha256` + `split_hash` + 题数 250 + **dev 桶摘要** |
| dataset 身份 | 冻结路径 + 字节 `sha256`（split 钉不住题面被换掉） |

- 切分规则复算改用 `expected_family`（仓内常量），不再用文件自述的 family；
- 新增 `load_frozen_split()` 作为**运行路径唯一入口**（身份闸 → 内容五道闸），
  `materialize_split()` / `dev_item_ids()` / `run_round()` 全部经它；
- 新增 `assert_frozen_dataset()`，与 split 同级，长在 `_dev_bundle()` 上（运行路径，
  不只是体检命令）；
- 常量本身由回归 `test_frozen_constants_match_the_committed_blobs` 用
  `git cat-file blob HEAD:` 复算守着——常量与仓内已提交冻结件漂移即红。

新错误码：`split_family_mismatch` / `split_salt_mismatch` / `split_bytes_not_frozen` /
`split_not_frozen_path` / `split_identity_mismatch` / `dataset_bytes_not_frozen` /
`dataset_not_frozen_path` / `dataset_missing` / `bad_expected_family`。

**V2 实测**：同一份伪造件 → `REJECTED [split_family_mismatch]`；
就地给仓内 split 加一个换行 → `REJECTED [split_bytes_not_frozen]`。

### 二（阻断）· HTTP 路径捕获错位 → `curl rc=52 Empty reply` — `lab/fastlane/web.py`

**V1 的错在哪**：`round_rows()` / `load_items_for()` 已经在核心边界把 `ContractError`
翻译成 `FastlaneError` 了，而 HTTP 层仍写 `except ContractError`——捕获的是**再也不会
到达此处的类型**；`read_round()` 的 `round_tampered` 更是完全没接。异常直穿
`socketserver`，连接被丢弃。

**在 `eeae494` 树上实测**（真服务、真 curl）：

```text
篡改轮次记录后 GET /round   -> curl rc=52 / http 000   服务端 traceback round_tampered
删掉 notebook 一行后 GET    -> curl rc=52 / http 000
伪造 bundle seal 后 GET     -> curl rc=52 / http 000
GET /（历史页）              -> 200，但坏轮**整条消失**（是否出现: False）
```

**闭合方式**：三处按真实类型捕获（`FastlaneError` 优先，`ContractError` 并列保留），
各自渲染一整页人类错误页（阶段 + 错误码 + 人话 + 该做什么 + 别的轮次不受影响）；
另加兜底 `_guard()`，任何漏网异常也落成错误页——**且只在尚未发出响应时兜底**，
以免把半截响应接上第二个响应头。

- `bundle` 验签失败不再降级成"题面留空、照样出页"：封印语义是防 holdout 冒充 dev，
  验不过就无法证明页面上的题来自 dev，**整轮不展示**（fail-closed 方向）；
- `/new?from=` 区分 `round_not_found`（404）与"记录不可信"（500），不再混成 404；
- 历史页不再 `continue` 掉坏轮：新增 `loop.scan_rounds()` 返回 `(可读, 读不出来的)`，
  页面与 CLI `list` 都把坏轮带错误码显示出来，只是不展示其内容。

**V2 实测**：上述四种情形分别得到 `http 500 / curl rc=0`，页面含错误码与横幅；
历史页同时列出好轮与坏轮（`round_tampered` 可见），坏轮内容不展示。

### 三（阻断）· 结果页截断身份值

## 已知缺口（如实列出，未修）

前五条是 V1 已披露的残余风险，**本轮不借机顺手改**（不碰并发、O(n²)、
公开 `record_hash`、假设折叠）：

1. **CLI 并发无锁**。页面层用 `_RUN_LOCK` 保证同一时刻只跑一轮；手动开两个
   CLI `run` 进程跑同一请求，两边都会通过"这轮还没跑过"的检查而各跑一遍模型。
2. **`ProbeNotebook._indexed` 是 O(n²)**（每次 append 重读整个索引）。
   **这是科学核心里的实现，本轮不改核心。**
3. **`record_hash` 只防误改，不防有意伪造** —— 算法公开，有写权限者可重算。
4. **假设折成单行不可逆**：`"a\nb"` 与 `"a / b"` 共用 `probe_id`；原文另存 `hypothesis_raw`。
5. **未做真人验收**。以上全是作者自测。`08` §3 要楠亲自走一遍
   "查看 → 修改 → 新跑"，在那之前只能叫**等待真人验收**。

V2 新增的两条边界：

6. **冻结坐标是"钉住"，不是"自动跟随"**。`data/splits|benchmarks/ifeval_zh_v1.json`
   将来若**正当地**更新，快道会 fail-closed 停下来，需要人同步改
   `split_adapter.py` 里的 `FROZEN_*` 常量。这是有意的：数据身份换了本就该有人过目。
   常量与仓库是否漂移由 `test_frozen_constants_match_the_committed_blobs` 守着；
   **该测试在没有 git 的环境里 skip**——skip 不是 PASS，届时只剩常量这一层。
7. **身份闸挡的是数据被换，挡不住有写权限者改代码**。能编辑 `split_adapter.py`
   的人可以把常量一并改掉。与第 3 条同源：这些机制提供的是**可发现性**，
   不是权限控制。

V4 新增的一条边界：

9. **让位后的端口每次都可能不同**。无参数入口在 8787 被占时用的是系统分配的
   临时端口，所以两次启动的 URL 不一样——书签会失效，以终端打印的地址为准。
   这是本机单用户工具的合理代价；要固定端口就显式 `--port`（那时被占会报错，
   不会悄悄换）。

V3 新增的一条边界：

8. **旧轮里"当初用的是哪份数据"只记不判**。轮次记录里存着当时的
   `dataset_sha256` / `split_sha256`，V3 的闸只保证**今天不能再拿它当结果交付**，
   并不会在 `show` / 详情页上回头判定"这一轮当初是不是在坏数据上跑的"。
   人自己拿记录里的 sha256 与冻结常量一比即可看出来，但页面不替他做这个判断——
   那属于新功能，本轮不扩。按 Codex 的要求，`record_hash` 可删除/重算的风险
   同样不在本轮扩修范围内。
