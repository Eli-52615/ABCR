> 性质：**目标沟通卡**，不是实现任务卡。本卡讲"要达成什么、什么算达成、什么不许碰"；怎么实现由你们（Code 侧）自定。
> 读者：并行 Code 窗集群（假定可开 16 窗、每窗 15 子 agent、token 与算力不设限、连续运转）。
> 上位文档（本卡不复述、你们必读）：《ABCR-自动化-工程包A/B/C V1.0》三份、《ABCR-W1执行方案 V1.0 + V1.1补丁》、《ABCR-W1终验报告》《ABCR-云日执行报告-20260714》、工程进展史阶段 3–4。
> 硬前提：**完全适配既有自动化工作流**——复用账本/状态机/信封/令牌/审计/独立复算/锁盲/watchdog/云生命周期，不另起炉灶、不绕过任何既有门。

## 1. 目标一句话

在既有控制面之上加一层**探索语义层**，实现：

```
楠写《实验目标书》 → 工作流编译成批次(信封+config)并执行(经楠签令牌)
→ 实验体(rig)返回结果 → 工作流产出《轮报告》(证据段 + 工程侧机器反思段 + 楠的反思留白)
→ 楠改进目标书 → 下一轮
```

楠在"目标→结果"的中间过程**零操作**（唯一例外：审批签令牌、租卡报参数）；但机制必须赋予楠**随时下钻到任意粒度**的检查与干预能力（见 §2-d、§2-g）。

## 2. 交付物（目标态 + 验收判据；实现自定）

**a. 《实验目标书》schema + 校验器。**
自然语言假设区（楠亲笔，逐字入档）+ 结构化区：`personas[]`（spec 正文、theory_label、逐任务族 predicted_direction、dose∈{weak,strong}、parent/version）、`families[]`、`arms`（自动含 vanilla；③ᴸ 配对按 §2-c 规则生成）、`budget`、`deadline`、`split: dev-only`。
验收：字段缺失/越界/split≠dev → **拒绝并输出人类可读缺陷清单**，不静默补全、不猜测（fail-closed，延续阶段 4 全线纪律）。

**b. 目标→计划编译器（planner 语义扩展）。**
goal → envelope(s)+configs，全自动；歧义 → 返回澄清问题清单终止，不出信封。
硬门新增：**假设先于审批**——goal 定稿 commit 时间戳必须早于该批 `batch_approved` 账本事件；此判据同时作为 **A 审计新增核验项**（audit item 扩展，进审计报告）。
编译器保持**零 LLM**（延续 Governor planner v0 立场）；规则覆盖不了的情形走"澄清清单"，不走模型猜测。

**c. ③ᴸ 同长度指令对照自动生成器。**
对每个 persona 变体生成同长度、去人格语义、纯任务展开的对照文本（生成规则冻结成文档并入契约谱系）；③ᴸ 自身过 manipulation-check（自检标记率/hedging 率，词表用 constants 冻结版），非中性程度随轮报告发布——延续 V1.3"夹逼对照"定位，禁止当纯净中性对照解释。

**d. 轮报告生成器（原"反思包"，更名）。**
证据段：分数表、相对 vanilla 与父本的差值、③ᴸ 夹逼位置、方差/seed 间波动、行为学指标（长度、hedging 率、自检标记率——判分器现成产出，直接汇总）、判例转写（每变体×每族抽 k 条渲染成可读 transcript，k 默认 3）、异常格标红。
工程侧机器反思段：数据质量问题、疑似混淆信号、功效/方差提示、设计改进**建议**。此段可用 LLM 撰写，但三条钉死：只读 dev 段结果；输出为建议、**永不自动生效**（任何设计变更必须经楠改目标书）；对 cal/holdout 结构性不可见（复用 split 隔离与 C2-5 锁盲路径）。
楠侧反思留白：四解释槽模板（信息性/计算调制/分布选择/内部状态）+ 空白假设区，楠亲笔填写后随轮归档。

**e. 轮索引 + 全粒度下钻。**
`round_id` 串起 goal → envelopes → runs → steps → scores → judge 原始调用 → audit → 轮报告；一条命令从轮级钻到单条生成的**渲染后完整 prompt** 与 judge 原始请求/响应。能复用 C1-7 三层钻取的就扩展它，不重造。

**f. 同日轮回时序编排。**
端到端时钟目标：**晨定稿目标书 → 晚出轮报告**，或**晚定稿 → 次晨出报告**。链路：编译 →（可选 Mac 3B 预检）→ 云批（7B bf16）→ A 审计 + C 独立复算 → 轮报告。楠的人手环节压缩到：签令牌、租卡报参数（沿 B2-8 `cloud.py` 流程）。若现状还有第三个必须人手的环节，**明确列出**并给最小化方案，不许静默假设楠会补位。
轮内默认规模参数化：`variants=3`（楠已定上限）、seeds、题量均入 goal schema。

**g. 楠的干预面。**
`abcrctl` 扩展（或等价 CLI）：round status / pause / abort / drill；一切干预动作入账本（新事件词走契约修订广播流程）。暂停与中止必须与幂等续跑兼容（被停的批可续、可废弃，账目清晰）。

**h. 探索人格工件与注册表。**
工件格式沿锚 trait 工件格式（B1-11），**抽取题集字段允许后补**（仅收敛后做向量时才需要）；注册表记 id/version/parent/theory_label/假设指针（指向目标书对应段落的锚）。
**种子内容不预置**：不得把 V1.3 的四个策略人格预填为待测对象（楠裁决：它们降为参考例）。optimistic 与 conscientiousness 的既有向量以**测量锚（仪器）**身份挂接投影统计，不进待测集。

## 3. 硬约束与不做清单

1. 冻结契约区（schema、事件词表、路径、错误码）改动一律走"契约修订 + 广播"流程，不许就地改。
2. 不引入绕过令牌的自动派发；信封内自动派发开关维持 C 包 §7.2 的"只交规格不接线"状态。
3. LLM 组件只允许出现在轮报告反思段与 transcript 转写；**不得**出现在编译裁决、门控判定、审计、复算路径上。
4. 测试纪律延续：fail-closed 断言方向；真模型/付费用例打 `golden` 标记；默认回归 `-m "not golden"`；604 项无计费基线不回退。
5. 模型默认 Qwen2.5-7B-Instruct（钉版沿 models.yaml），但**模型选择是楠的待决参数（Q5）**——一切新代码不得硬编码模型名，全部走 config。
6. 探索一切批次 split=dev；cal/holdout 目录对探索链路结构性不可达（越界 = 审计 FAIL + triage 告警）。

## 6. 验收态（7 小时门）

1. fake-engine 全链端到端演练一次：目标书 → 校验 → 编译 → 信封 → （fixture 令牌）→ 执行 → 审计+复算 → 轮报告落盘，零人工干预（签批环节 fixture 代表）。
2. Mac 3B 真链一遍（citable=false）：≥1 个楠自拟人格占位变体 + vanilla + ③ᴸ，轮报告完整产出，下钻命令实测可达单条 prompt。
3. 拒绝路径实测：坏目标书被拒且缺陷清单可读；假设晚于审批被 A 审计 FAIL；split 越界被拦。
4. 604 项基线全绿不回退；新增测试全部 fail-closed 方向。
5. 对抗窗至少一轮击打记录归档（发现即修，修不完的如实列 residual）。
6. 诚实边界声明入交付报告：7 小时门 = 可用 + 初检；**深度对抗回归为紧随其后的独立批次**（沿"修复者自测不可信"教训），云上同日轮回的真实排练在下一个云窗完成。
