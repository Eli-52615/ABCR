## 1. 缺陷机理(一句话)

冻结树以"全部文件条目 hash"为身份、出厂零 `.pyc`;而 root 调用冻结 `env/bin/python -I` 时,`-I` 隐含 `-E` 使 `PYTHONDONTWRITEBYTECODE=1` 环境变量失效,root 又无视目录只读位,于是**解释器启动阶段的 stdlib import 就把 `__pycache__/*.pyc` 写进被校验的树**,随后一切全树校验 fail-closed,且重试永久失败(pending receipt 的 `sealed_tree_hash` 已固定)。非 root 服务 UID 被 0550 目录挡住,不受影响;**威胁面 = 所有以 root 运行冻结 Python 的调用点**。

- `scripts/bootstrap_abcr_genesis.py` `_run_lkg_broker_confirm`(约 621–630 行)与 `_run_normal_installer`(约 687–695 行):子进程 argv 均为 `[final/env/bin/python, "-I", ...]`,无 `-B`;以 root 运行,启动即污染 sealed final → broker-confirm 在 `seal_broker.py` seal_tree 回放校验(约 212 行)fail;重试在 `stage_reviewed_release`(约 475–491 行)/`ensure_pending_receipt`(约 532 行)fail。**genesis 必砖,恢复只能人工删 pyc(本身又是 off-ceremony 动作)。**
