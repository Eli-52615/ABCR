# ABCR reviewed-runtime release and first-genesis runbook

This is the fail-closed path from one exact reviewed Git commit to the first
root-owned ABCR release.  It never installs or executes service code from a
checkout and never manufactures a verifier key or attestation.  Sections 1--5
build, review and install without loading launchd; sections 6--9 are the
separate, explicit human/root activation ceremony.

Status words are deliberately distinct:

- `UNTRUSTED_CANDIDATE`: deterministic bytes were built, but no reviewer has
  authorized them.
- `BLOCKED / SIGNED_VERIFICATION_REQUIRED`: structural doctor passed; a real
  sandbox test and external verifier signature are still required.  Exit 78 is
  the expected success condition for this *blocked* phase.
- `READY_FOR_HUMAN_ROOT_REVIEW_COPY`: the exact candidate has a valid PASS
  attestation and a canonical twelve-service release manifest.  This is not
  root authority and does not start anything.

## 1. Inputs and immutable boundaries

Record these values in the review ticket.  A branch name, tag, `HEAD`, dirty
working-tree byte, unsigned JSON, or key generated by the candidate is invalid.
Every value written as `<...>` below is a required human/external input; replace
it before execution.  Pasting the angle brackets themselves is an error, never
a request for the script to guess.

```sh
ABCR_REVIEWED_REPO=/Users/superagent/shared-brain/ABCR/abcr
ABCR_REVIEWED_COMMIT=<exact-40-lowercase-Git-SHA>
ABCR_CANONICAL_PYTHON=/Users/superagent/shared-brain/ABCR/abcr/.venv312/bin/python
ABCR_PYTHON_HOME=/Users/superagent/.local/share/uv/python/cpython-3.12.13-macos-aarch64-none
ABCR_SITE_PACKAGES=/Users/superagent/shared-brain/ABCR/abcr/.venv312/lib/python3.12/site-packages
ABCR_REVIEW_VERIFIER_PUB=<external-independent-review-verifier-public-key>
ABCR_BUILD_ROOT=<new-directory-under-/Users/superagent/.abcr-build>
```

The public key must already exist as a single-link, non-symlink regular file
without group/world write permission.  Its private key stays outside the
candidate, release, checkout, and this runbook.

The builder exports only the finite production allowlist.  `data/`, tests,
fixtures, reports, VCS metadata and the working tree do not enter the candidate.
It materializes the existing CPython 3.12 home and site-packages offline; do not
run `pip`, `uv`, Ollama installation, or a model download in this procedure.

## 2. Execute the reviewed builder, not the checkout copy

Export the driver from the exact Git object, then execute it with the reviewed
`src/abcr` from the same object.  The output runtime subsequently carries its
own reviewed builder and no longer depends on `PYTHONPATH`.

```sh
/bin/mkdir -m 0700 "$ABCR_BUILD_ROOT"
/bin/mkdir -m 0700 "$ABCR_BUILD_ROOT/reviewed-driver"
/usr/bin/git -C "$ABCR_REVIEWED_REPO" archive "$ABCR_REVIEWED_COMMIT" \
  scripts/build_reviewed_runtime.py src/abcr | \
  /usr/bin/tar -x -C "$ABCR_BUILD_ROOT/reviewed-driver"

PYTHONPATH="$ABCR_BUILD_ROOT/reviewed-driver/src" \
  "$ABCR_CANONICAL_PYTHON" -P \
  "$ABCR_BUILD_ROOT/reviewed-driver/scripts/build_reviewed_runtime.py" build \
  --repo "$ABCR_REVIEWED_REPO" \
  --reviewed-commit "$ABCR_REVIEWED_COMMIT" \
  --python-home "$ABCR_PYTHON_HOME" \
  --site-packages "$ABCR_SITE_PACKAGES" \
  --review-verifier-public-key "$ABCR_REVIEW_VERIFIER_PUB" \
  --output "$ABCR_BUILD_ROOT/candidate"
```

The result must report `UNTRUSTED_CANDIDATE`, an exact candidate tree hash,
runtime hash, reviewed commit and two `resource_mirrors`.  Each mirror binds a
human-reviewed `configs/research/...` file to the byte-identical package
resource used by installed `python -I`; either copy missing or differing is a
hard failure.

Run the candidate doctor from outside the checkout and assert the intentional
78 result:

```sh
set +e
"$ABCR_BUILD_ROOT/candidate/env/bin/python" -I \
  "$ABCR_BUILD_ROOT/candidate/scripts/build_reviewed_runtime.py" doctor-candidate \
  --candidate "$ABCR_BUILD_ROOT/candidate" \
  --repo "$ABCR_REVIEWED_REPO" \
  --reviewed-commit "$ABCR_REVIEWED_COMMIT"
ABCR_DOCTOR_RC=$?
set -e
test "$ABCR_DOCTOR_RC" -eq 78
```

## 3. External independent-verifier gate

STOP here until the independent verifier/test-controller has:

1. tested the printed candidate tree hash with the real deny-default candidate
   sandbox and the fixed command
   `candidate/env/bin/python -I -m abcr.control.candidate_oracle_adapter`;
2. independently compared the oracle result (the child has no verdict power);
3. produced a PASS `VerificationAttestation` signed by the private key
   corresponding to `ABCR_REVIEW_VERIFIER_PUB`.

There is intentionally no command in this repository that can mint that key or
substitute an unsigned PASS document.  On the current Mac mini this is an
external human/reviewer gate if the verifier key and signed attestation have not
been provisioned.

After receiving the attestation, record its path and finalize:

```sh
ABCR_VERIFICATION_ATTESTATION=<external-signed-verification-json>
/bin/mkdir -m 0700 "$ABCR_BUILD_ROOT/release-staging"

"$ABCR_BUILD_ROOT/candidate/env/bin/python" -I \
  "$ABCR_BUILD_ROOT/candidate/scripts/build_reviewed_runtime.py" finalize \
  --candidate "$ABCR_BUILD_ROOT/candidate" \
  --attestation "$ABCR_VERIFICATION_ATTESTATION" \
  --verifier-public-key "$ABCR_REVIEW_VERIFIER_PUB" \
  --staging-root "$ABCR_BUILD_ROOT/release-staging" \
  --repo "$ABCR_REVIEWED_REPO" \
  --reviewed-commit "$ABCR_REVIEWED_COMMIT"

ABCR_RELEASE_ID=<REL-id-printed-by-finalize>
ABCR_RELEASE_STAGING="$ABCR_BUILD_ROOT/release-staging/$ABCR_RELEASE_ID.staging"

"$ABCR_RELEASE_STAGING/env/bin/python" -I -B \
  "$ABCR_RELEASE_STAGING/scripts/build_reviewed_runtime.py" doctor-release \
  --release "$ABCR_RELEASE_STAGING" \
  --attestation "$ABCR_VERIFICATION_ATTESTATION" \
  --verifier-public-key "$ABCR_REVIEW_VERIFIER_PUB" \
  --repo "$ABCR_REVIEWED_REPO" \
  --reviewed-commit "$ABCR_REVIEWED_COMMIT"
```

Both commands must report the same commit, release ID, candidate tree hash,
verification hash, release-manifest hash and exactly twelve service modules.

## 4. Human comparison and atomic root-owned review copy

This is a separate authority action.  Resolve `ABCR_RELEASE_ID` from the
finalizer output; never derive or shorten it.  Refuse an existing destination
or incoming path.

```sh
ABCR_REVIEW_ROOT="/Library/Application Support/ABCR-Genesis/reviewed"
ABCR_REVIEW_FINAL="$ABCR_REVIEW_ROOT/$ABCR_RELEASE_ID"
ABCR_REVIEW_INCOMING="$ABCR_REVIEW_ROOT/.$ABCR_RELEASE_ID.incoming"

sudo /usr/bin/install -d -o root -g wheel -m 0755 \
  "/Library/Application Support/ABCR-Genesis" "$ABCR_REVIEW_ROOT"
sudo /bin/test ! -e "$ABCR_REVIEW_FINAL"
sudo /bin/test ! -L "$ABCR_REVIEW_FINAL"
sudo /bin/test ! -e "$ABCR_REVIEW_INCOMING"
sudo /bin/test ! -L "$ABCR_REVIEW_INCOMING"
sudo /bin/cp -pR "$ABCR_RELEASE_STAGING" "$ABCR_REVIEW_INCOMING"
sudo /usr/sbin/chown -R root:wheel "$ABCR_REVIEW_INCOMING"

sudo "$ABCR_REVIEW_INCOMING/env/bin/python" -I -B \
  "$ABCR_REVIEW_INCOMING/scripts/build_reviewed_runtime.py" doctor-release \
  --release "$ABCR_REVIEW_INCOMING" \
  --attestation "$ABCR_VERIFICATION_ATTESTATION" \
  --verifier-public-key "$ABCR_REVIEW_VERIFIER_PUB" \
  --repo "$ABCR_REVIEWED_REPO" \
  --reviewed-commit "$ABCR_REVIEWED_COMMIT"

sudo /bin/mv "$ABCR_REVIEW_INCOMING" "$ABCR_REVIEW_FINAL"
sudo "$ABCR_REVIEW_FINAL/env/bin/python" -I -B \
  "$ABCR_REVIEW_FINAL/scripts/build_reviewed_runtime.py" doctor-release \
  --release "$ABCR_REVIEW_FINAL" \
  --attestation "$ABCR_VERIFICATION_ATTESTATION" \

  --repo "$ABCR_REVIEWED_REPO" \
  --reviewed-commit "$ABCR_REVIEWED_COMMIT"
```

Root ownership does not alter the committed tree hash; a mode or byte change
does and must be rejected.

## 5. One-time human/root genesis authority

Generate a non-authorizing draft from the fixed reviewed tree:

```sh
ABCR_AUTHORITY_DRAFT="$ABCR_BUILD_ROOT/genesis-authority.draft.json"
ABCR_AUTHORITY_APPROVED="$ABCR_BUILD_ROOT/genesis-authority.approved.json"

sudo "$ABCR_REVIEW_FINAL/env/bin/python" -I -B \
  "$ABCR_REVIEW_FINAL/scripts/bootstrap_abcr_genesis.py" \
  --authority-draft \
  > "$ABCR_AUTHORITY_DRAFT"
```

The draft derives `reviewed_commit` exclusively from the release's
manifest-bound `reviewed-source.json`.  `--reviewed-commit` remains available
only as an optional comparison assertion; it cannot supply or relabel commit
identity and a mismatch is `BLOCKED`.

The human must compare the full commit, release ID, reviewed path, release
manifest hash, source tree hash, expected receipt, every finite TCB hash and the
external verifier-key fingerprint against the preceding outputs.  Only after
that comparison, canonicalize the approval (do not hand-edit/hash JSON):

```sh
sudo /usr/bin/cmp "$ABCR_REVIEW_VERIFIER_PUB" \
  "$ABCR_REVIEW_FINAL/trust/review-verifier-attestation.pub"
sudo /usr/bin/shasum -a 256 \
  "$ABCR_REVIEW_FINAL/trust/review-verifier-attestation.pub"

sudo "$ABCR_REVIEW_FINAL/env/bin/python" -I -B \
  "$ABCR_REVIEW_FINAL/scripts/build_reviewed_runtime.py" approve-authority \
  --draft "$ABCR_AUTHORITY_DRAFT" \
  --output "$ABCR_AUTHORITY_APPROVED" --human-reviewed

ABCR_GENESIS_AUTHORITY_ID=<64-hex-id-printed-by-approve-authority>
sudo /bin/test ! -e "/Library/Application Support/ABCR-Trust/genesis-authority-v1.json"
sudo /usr/bin/install -o root -g wheel -m 0444 "$ABCR_AUTHORITY_APPROVED" \
  "/Library/Application Support/ABCR-Trust/genesis-authority-v1.json"
```

Before genesis, install/check the finite service identities from the reviewed
release.  This helper creates users/groups only; it installs no code, key, ACL,
or launchd job:

```sh
ABCR_AUTHORITY_SHA=40fd5fb21ff33d7da84648562c6dc12d68f15444dfea60379132af820510d0d1
sudo "$ABCR_REVIEW_FINAL/scripts/bootstrap_abcr_accounts.sh" \
  --install-reviewed "$ABCR_AUTHORITY_SHA"
sudo "$ABCR_REVIEW_FINAL/scripts/bootstrap_abcr_accounts.sh" --check
```

Both account modes fail closed unless `abcr-dataset-read` contains exactly
`abcr-itempool` and `abcr-auditor`.  The gate compares direct short names,
direct GeneratedUIDs, forbids every nested group, and enumerates every user in
the macOS directory search node to check primary/nested/effective membership.
An extra member such as `superagent`, `abcr-human`, or an unknown GUID is
`BLOCKED`.  The helper intentionally does not remove that identity: stop,
investigate the directory change, and repeat the reviewed ceremony after an
administrator has corrected it explicitly.

The frozen dataset is a separate scientific input and is never packaged in the
code release.  Stage the two pinned source files in the fixed root-only source
directory, then use the reviewed importer.  It independently enforces commit
`6d753307150bb4cf69d83e705fa737da07c738be`, both byte hashes, 250 unique IDs,
the 42/91/117 split and the frozen split hash.

```sh
ABCR_DATASET_SOURCE="/Library/Application Support/ABCR-Dataset-Sources/ifeval-zh-v1-6d753307150b"
sudo /usr/bin/install -d -o root -g wheel -m 0750 \
  "/Library/Application Support/ABCR-Dataset-Sources" "$ABCR_DATASET_SOURCE"
sudo /usr/bin/install -o root -g wheel -m 0440 \
  "$ABCR_REVIEWED_REPO/data/benchmarks/ifeval_zh_v1.json" \
  "$ABCR_DATASET_SOURCE/benchmark.json"
sudo /usr/bin/install -o root -g wheel -m 0440 \
  "$ABCR_REVIEWED_REPO/data/splits/ifeval_zh_v1.json" \
  "$ABCR_DATASET_SOURCE/split-source.json"
sudo /bin/chmod 0550 "$ABCR_DATASET_SOURCE" \
  "/Library/Application Support/ABCR-Dataset-Sources"
sudo "$ABCR_REVIEW_FINAL/env/bin/python" -I -B \
  "$ABCR_REVIEW_FINAL/scripts/import_abcr_dataset.py" \
  --install-reviewed "$ABCR_AUTHORITY_SHA"
sudo "$ABCR_REVIEW_FINAL/env/bin/python" -I -B \
  "$ABCR_REVIEW_FINAL/scripts/import_abcr_dataset.py" --check
sudo "$ABCR_REVIEW_FINAL/env/bin/python" -I -B \
  "$ABCR_REVIEW_FINAL/scripts/import_abcr_dataset.py" --check-live
```

The only accepted dataset output is
`/Library/Application Support/ABCR-Datasets/1402dec503f9c5345ecb0a9c709028d6a1d32cfb8a0f2fe1dd0f3c65248c6faa/`.

`--check` proves immutable bytes, owner/group/mode, and rejects any named or
inherited macOS ACL that grants read/list/search to a `must_deny` identity.
`--check-live` is the separate LIVE gate: it refuses non-root/non-macOS hosts,
demanding the same exact `abcr-dataset-read` direct/GUID/nested/effective group
proof before filesystem probes.  It then
drops child processes to `abcr-itempool`, `abcr-auditor`, and every denied UID,
and requires both authorized identities to list/open/read while every denied
identity receives actual `EACCES`/`EPERM` for directory lists and file opens.
A missing account, failed UID downgrade, missing path, or indeterminate error
is `BLOCKED`; ordinary CODE_RC fixtures cannot turn it into a live pass.

Now execute the one-time ceremony:

```sh
sudo "$ABCR_REVIEW_FINAL/env/bin/python" -I -B \
  "$ABCR_REVIEW_FINAL/scripts/bootstrap_abcr_genesis.py" \
  --genesis-reviewed "$ABCR_GENESIS_AUTHORITY_ID" --human-required
```

It creates a pending receipt, establishes the exact reviewed seal broker as the
first rollbackable LKG, asks that broker to revalidate the same release, removes
the pending marker, invokes the normal receipt-gated installer, and writes a
completion record with `launchd_loaded:false` and `services_started:false`.
Failure retains the exact LKG/receipt for reviewed retry and writes no false
completion.

## 6. Genesis 后初始化：禁止第二次运行安装器

先保留 genesis 输出的原值。不要从目录名猜测，也不要缩短 ID：

```sh
ABCR_RECEIPT_ID=<genesis-输出的-exact-64-hex-receipt>
ABCR_SEALED_RELEASE="/Users/superagent/.abcr/releases/$ABCR_RELEASE_ID"
ABCR_HUMAN_DIR="/Users/abcr-human/Library/Application Support/ABCR-Human"
ABCR_HUMAN_STAGING="/Users/superagent/Library/Application Support/ABCR-Human-staging"
ABCR_LAUNCHD_ROOT=/Library/LaunchDaemons

sudo /bin/test -d "$ABCR_SEALED_RELEASE"
sudo /bin/test ! -L "$ABCR_SEALED_RELEASE"
sudo /bin/test -f "/Library/Application Support/ABCR-Attest/release-receipts/$ABCR_RECEIPT_ID.json"
sudo /bin/test ! -L "/Library/Application Support/ABCR-Attest/release-receipts/$ABCR_RECEIPT_ID.json"
```

**硬禁令：不要再次执行 `install_abcr_runtime.py`。**
`bootstrap_abcr_genesis.py --genesis-reviewed` 已经用同一 receipt 唯一一次调用了
正常安装器，并留下 `launchd_loaded:false`、`services_started:false` 的 completion
record。重复运行既不补资格化，也会破坏“首次安装只发生一次”的审计口径。

### 6.1 人域、服务密钥、凭据/owner 前置和 ResearchMemory seal key

人域脚本幂等，但绝不覆盖现有私钥或不一致的 trust anchor：

```sh
sudo "$ABCR_SEALED_RELEASE/scripts/bootstrap_abcr_human.sh"
sudo "$ABCR_SEALED_RELEASE/scripts/bootstrap_abcr_service_keys.sh" \
  --install-reviewed "$ABCR_AUTHORITY_SHA"
sudo "$ABCR_SEALED_RELEASE/scripts/bootstrap_research_memory_seal.sh"

sudo "$ABCR_SEALED_RELEASE/scripts/bootstrap_abcr_service_keys.sh" --check
sudo "$ABCR_SEALED_RELEASE/scripts/bootstrap_research_memory_seal.sh" --check
```

预期最后两条分别打印 `service_signing_keys: all PASS` 和
`PASS: ResearchMemory root seal key and public trust anchor match`。任一
`BLOCKED` 都停；不要删除、重造或替换已存在的 key。

飞书凭据和人工核对后的 owner 四元组是**必须由人提前提供**的两个输入，不由安装器
猜测或生成：

- `$ABCR_HUMAN_STAGING/feishu.env`：只含本次 production app 的凭据；
- `$ABCR_HUMAN_STAGING/discovered-owner.json`：只含 owner 人工核对过的
  `open_id/tenant_key/chat_id/chat_type` 四元组，且 `chat_type` 必须为 `p2p`。

发现工具只可写 `.candidate.json`；它不能晋升 production owner。owner 必须当面核对
四元组，再创建最终 `discovered-owner.json`，并把两份 staging 文件的 SHA-256 记入
部署票据。任一输入缺失、是链接、多硬链接、非 `superagent` 持有或 mode 不是 `0600`
都停止。先只读核验，**不要打印 `feishu.env` 内容**：

```sh
sudo /bin/test -f "$ABCR_HUMAN_STAGING/feishu.env"
sudo /bin/test -f "$ABCR_HUMAN_STAGING/discovered-owner.json"
sudo /bin/test ! -L "$ABCR_HUMAN_STAGING/feishu.env"
sudo /bin/test ! -L "$ABCR_HUMAN_STAGING/discovered-owner.json"
sudo /usr/bin/stat -f '%Su:%Sg:%Lp:%l %N' \
  "$ABCR_HUMAN_STAGING/feishu.env" \
  "$ABCR_HUMAN_STAGING/discovered-owner.json"
sudo /usr/bin/shasum -a 256 \
  "$ABCR_HUMAN_STAGING/feishu.env" \
  "$ABCR_HUMAN_STAGING/discovered-owner.json"
```

两条 `stat` 都必须是 owner `superagent`、mode `600`、link count `1`；hash 必须与
部署票据一致。管理员随后与 owner 对照最终 JSON 的四个值；不要只对照 `open_id`。
首次复制使用 no-clobber 检查；production 目标已存在时只允许 `cmp` 字节一致，禁止
覆盖或使用 `mv`（staging 要保留供复核）：

```sh
sudo /bin/test ! -L "$ABCR_HUMAN_DIR/feishu.env"
sudo /bin/test ! -L "$ABCR_HUMAN_DIR/discovered-owner.json"

if sudo /bin/test -e "$ABCR_HUMAN_DIR/feishu.env"; then
  sudo /usr/bin/cmp "$ABCR_HUMAN_STAGING/feishu.env" "$ABCR_HUMAN_DIR/feishu.env"
else
  sudo /usr/bin/install -o abcr-human -g abcr-human -m 0600 \
    "$ABCR_HUMAN_STAGING/feishu.env" "$ABCR_HUMAN_DIR/feishu.env"
fi
if sudo /bin/test -e "$ABCR_HUMAN_DIR/discovered-owner.json"; then
  sudo /usr/bin/cmp "$ABCR_HUMAN_STAGING/discovered-owner.json" \
    "$ABCR_HUMAN_DIR/discovered-owner.json"
else
  sudo /usr/bin/install -o abcr-human -g abcr-human -m 0600 \
    "$ABCR_HUMAN_STAGING/discovered-owner.json" \
    "$ABCR_HUMAN_DIR/discovered-owner.json"
fi
sudo /usr/bin/stat -f '%Su:%Sg:%Lp:%l %N' \
  "$ABCR_HUMAN_DIR/feishu.env" \
  "$ABCR_HUMAN_DIR/discovered-owner.json"
```

production 两个文件必须都是 `abcr-human:abcr-human:600:1`。然后只从 sealed release
运行人域前置探针：

```sh
sudo "$ABCR_SEALED_RELEASE/scripts/check_human_signature_domain.sh"
```

它全部 PASS 只证明 OpenSSL/key/trust/spool **前置**，不证明 owner 飞书收发、live
approval、断线重放或整个 `LIVE_PILOT.approval` 已 PASS；这些只能由第 10 节真实验收。

### 6.2 显式初始化两个数据库

数据库初始化必须清空调用者环境，并以各自服务 UID、sealed Python 和 `-I` 执行。
这样管理员遗留的 `ABCR_HUMAN_*` 或测试路径不能改写 production 目标。它不会启动网络：

```sh
sudo -u abcr-human /usr/bin/env -i PATH=/usr/bin:/bin LC_ALL=C \
  ABCR_RELEASE_ID="$ABCR_RELEASE_ID" ABCR_ACTIVATION_STATE=ACTIVE \
  ABCR_SERVICE_LABEL=com.abcr.human-gateway PYTHONDONTWRITEBYTECODE=1 \
  PYTHONNOUSERSITE=1 PYTHONUTF8=1 "$ABCR_SEALED_RELEASE/env/bin/python" -I \
  -m abcr.control.human_gateway --init-db
sudo -u abcr-operator /usr/bin/env -i PATH=/usr/bin:/bin LC_ALL=C \
  ABCR_RELEASE_ID="$ABCR_RELEASE_ID" ABCR_ACTIVATION_STATE=ACTIVE \
  ABCR_SERVICE_LABEL=com.abcr.operator-reconciler PYTHONDONTWRITEBYTECODE=1 \
  PYTHONNOUSERSITE=1 PYTHONUTF8=1 "$ABCR_SEALED_RELEASE/env/bin/python" -I \
  -m abcr.control.operator --init-db
```

两条输出都必须含 `"ok": true`。随后检查 owner/mode：

```sh
sudo /usr/bin/stat -f '%Su:%Sg:%Lp %N' \
  "/Users/abcr-human/Library/Application Support/ABCR-Human/human.db" \
  "/Users/superagent/Library/Application Support/ABCR-Control/control.sqlite3"
```

预期分别由 `abcr-human`、`abcr-operator` 持有且 mode 为 `600`。研究账本由首个
owner-confirmed goal saga 创建；在此之前相关审批链保持 `BLOCKED` 是正确行为。

## 7. 三组件整代 selector 资格化

安装器只写了一个 `COMMITTED` 候选 generation；它尚不可执行。第一次 root
resolve 会在同一把锁内依次 doctor `launcher`、`seal-broker`、`test-controller`，
三者全部成功后才把整个 transaction 原子改为 `ACTIVE`。不是三次独立晋级。

```sh
sudo /usr/local/libexec/abcr-bootstrap-selector --resolve-only launcher
sudo /usr/local/libexec/abcr-bootstrap-selector --resolve-only seal-broker
sudo /usr/local/libexec/abcr-bootstrap-selector --resolve-only test-controller
```

三条都必须输出 `"ok": true`；首次调用资格化整代，后两条复读同一 ACTIVE
generation。任一 doctor 失败会把整个 generation 置为 `FAILED` 并共同回到上一个
generation；不要手改 pointer、transaction 或 last-known-good，也不要重跑安装器。
首次 genesis 没有可用共同前代时，停止并重新走新的 exact reviewed release。

当前代码已经实现 fail-closed 的整代选择与共同回退，但“故意安装坏 slot、真实
launchd 下自动回旧 slot、原 seal 能力恢复”尚须管理员在隔离维护窗实测；未实测前
`AUTONOMOUS_QUAL.bad_slot_rollback_drill=BLOCKED`，不得用 unit test 代替。

## 8. 最小三服务 probation，再扩到十二服务

### 8.1 只加载 seal broker、canary 和 activator

此时只允许下列三个 job。`bootstrap` 报 “service already loaded” 时先调查；不要
用 `kickstart -k` 掩盖旧 generation：

```sh
sudo /bin/launchctl bootstrap system \
  "$ABCR_LAUNCHD_ROOT/com.abcr.seal-broker.plist"
sudo /bin/launchctl bootstrap system \
  "$ABCR_LAUNCHD_ROOT/com.abcr.canary-controller.plist"
sudo /bin/launchctl bootstrap system \
  "$ABCR_LAUNCHD_ROOT/com.abcr.release-activator.plist"

sudo /bin/launchctl print system/com.abcr.seal-broker
sudo /bin/launchctl print system/com.abcr.canary-controller
```

## 9. AUTONOMOUS_QUAL 外部签名与 registry

这一节只资格化 `AUTONOMOUS_QUAL.adapter_egress_profile` 子门。它不生成私钥，
不自签，也不会把 `AUTONOMOUS_QUAL` 总门改成 PASS。外部 authority 私钥必须永远
留在 ABCR 消费机、release、checkout 和 registry 之外。

### 9.1 外部 authority 与 root-owned adapter 工件

外部资格化包必须先提供并由人审核：

- Ed25519 authority public key；
- 固定目录 `/Library/Application Support/ABCR-Bootstrap/adapters/mission-builder`
  的有限 runtime tree、唯一 executable、完整 runtime manifest/tree hash；
- exact argv（只允许一个 `{objective}` 占位）、argv/executable hash；
- root-owned deny-default Seatbelt profile；
- root-owned Unix egress broker socket 和 canonical policy；
- HTTPS endpoint 精确集合、90 天以内 expiry；
- AUTONOMOUS bundle schema 中的兼容 execution profile（它只参与 mission 包完整性，
  **不是**科学实验 compiler/dispatch 的授权来源）。

先在维护窗安装外部公钥；已存在时只能比对一致：

```sh
ABCR_AUTOQUAL_PUB_IN=<外部-authority-public-key>
ABCR_AUTOQUAL_PUB="/Library/Application Support/ABCR-Trust/autonomous-qualification-authority-v1.pub"
/bin/test -f "$ABCR_AUTOQUAL_PUB_IN"
/bin/test ! -L "$ABCR_AUTOQUAL_PUB_IN"
if sudo /bin/test -e "$ABCR_AUTOQUAL_PUB"; then
  sudo /usr/bin/cmp "$ABCR_AUTOQUAL_PUB_IN" "$ABCR_AUTOQUAL_PUB"
else
  sudo /usr/bin/install -o root -g wheel -m 0444 \
    "$ABCR_AUTOQUAL_PUB_IN" "$ABCR_AUTOQUAL_PUB"
fi
sudo /bin/test ! -L "$ABCR_AUTOQUAL_PUB"
sudo /usr/bin/stat -f '%Su:%Sg:%Lp %l %N' "$ABCR_AUTOQUAL_PUB"
```

预期 `root:wheel:444`、link count 1。adapter runtime、Seatbelt、egress policy 与
socket 必须由外部审查包按签名 core 的绝对路径先落成 root-owned、不可组/其他用户
写的真实节点；本仓库没有“下载一个 Codex/代理并自动信任”的命令。

adapter runtime 的唯一生产路径固定如下。外部包本身必须已经具有最终 mode；不要
现场 chmod 到“看起来能过”，否则 manifest/core 必须重新生成并重新外签：

```sh
ABCR_AUTOQUAL_ADAPTER_IN=<外部审查通过的有限-adapter-runtime目录>
ABCR_AUTOQUAL_ADAPTER_PARENT="/Library/Application Support/ABCR-Bootstrap/adapters"
ABCR_AUTOQUAL_ADAPTER_ROOT="$ABCR_AUTOQUAL_ADAPTER_PARENT/mission-builder"

/bin/test -d "$ABCR_AUTOQUAL_ADAPTER_IN"
/bin/test ! -L "$ABCR_AUTOQUAL_ADAPTER_IN"
/bin/test -z "$(/usr/bin/find "$ABCR_AUTOQUAL_ADAPTER_IN" -type l -print -quit)"
/bin/test -z "$(/usr/bin/find "$ABCR_AUTOQUAL_ADAPTER_IN" -type f -links +1 -print -quit)"
sudo /bin/test -d "$ABCR_AUTOQUAL_ADAPTER_ROOT"
sudo /bin/test ! -L "$ABCR_AUTOQUAL_ADAPTER_ROOT"
sudo /bin/test -z "$(sudo /usr/bin/find "$ABCR_AUTOQUAL_ADAPTER_ROOT" -mindepth 1 -print -quit)"
sudo /bin/cp -pR "$ABCR_AUTOQUAL_ADAPTER_IN/." "$ABCR_AUTOQUAL_ADAPTER_ROOT/"
sudo /usr/sbin/chown -R root:abcr-builder "$ABCR_AUTOQUAL_ADAPTER_ROOT"
sudo /bin/test -z "$(sudo /usr/bin/find "$ABCR_AUTOQUAL_ADAPTER_ROOT" -type l -print -quit)"
sudo /bin/test -z "$(sudo /usr/bin/find "$ABCR_AUTOQUAL_ADAPTER_ROOT" -type f -links +1 -print -quit)"
```

installer 已预建一个空的 root-owned `0550` placeholder，所以这里只允许从“确实为空”
状态装入一次。复制中断时 registry 仍不存在、执行保持 deny；保留现场调查，不要盲目
叠加第二份 runtime。最终目录必须仍由 root 持有且不可 group/world write。

在生成 core 前记录最终节点。`ABCR_AUTOQUAL_EGRESS_POLICY` 与 socket 必须换成外部
包批准的绝对路径；socket 不存在就停止，不能用普通文件或 seal-broker socket 冒充：

```sh
ABCR_AUTOQUAL_SEATBELT="/Library/Application Support/ABCR-Bootstrap/config/mission-builder.sb"
ABCR_AUTOQUAL_EGRESS_POLICY=<外部审查通过的-root-owned-canonical-policy.json>
ABCR_AUTOQUAL_EGRESS_SOCKET=<外部审查通过的-root-owned-Unix-broker.socket>

sudo /usr/bin/stat -f '%Su:%Sg:%Lp %l %HT %N' \
  "$ABCR_AUTOQUAL_SEATBELT" "$ABCR_AUTOQUAL_EGRESS_POLICY"
sudo /bin/test ! -L "$ABCR_AUTOQUAL_SEATBELT"
sudo /bin/test ! -L "$ABCR_AUTOQUAL_EGRESS_POLICY"
sudo /bin/test -S "$ABCR_AUTOQUAL_EGRESS_SOCKET"
sudo /usr/bin/stat -f '%Su:%Sg:%Lp %HT %N' "$ABCR_AUTOQUAL_EGRESS_SOCKET"
sudo /usr/bin/shasum -a 256 "$ABCR_AUTOQUAL_SEATBELT" \
  "$ABCR_AUTOQUAL_EGRESS_POLICY"
```

文件预期 root-owned、link count 1、不可 group/world write；Unix socket 也必须由
root broker 持有。最终 runtime manifest 必须枚举每个目录/文件的 path、kind、mode、
size、SHA-256，且 core 的 `runtime_tree_sha256` 绑定整个 canonical manifest。

### 9.2 draft、外签、assemble、root verify/install

外部资格化者先生成完整 canonical core JSON。字段全集以已 seal 的
`src/abcr/control/autonomous_qualification.py` 的 `_CORE_FIELDS` 及子字段为准；
`qualification_id` 必须由完整 core 内容导出，不能手写占位。然后执行：

```sh
ABCR_AUTOQUAL_CLI="$ABCR_SEALED_RELEASE/scripts/qualify_abcr_autonomous.py"
ABCR_AUTOQUAL_WORK="$ABCR_BUILD_ROOT/autonomous-qualification"
ABCR_AUTOQUAL_CORE="$ABCR_AUTOQUAL_WORK/core.json"
ABCR_AUTOQUAL_DRAFT="$ABCR_AUTOQUAL_WORK/draft.json"
ABCR_AUTOQUAL_SIGNING_CORE="$ABCR_AUTOQUAL_WORK/attestation-core.json"
ABCR_AUTOQUAL_ATTESTATION="$ABCR_AUTOQUAL_WORK/external-attestation.json"
ABCR_AUTOQUAL_BUNDLE="$ABCR_AUTOQUAL_WORK/signed-bundle.json"
ABCR_AUTOQUAL_KEY_ID="$(/opt/homebrew/opt/openssl@3/bin/openssl pkey \
  -pubin -in "$ABCR_AUTOQUAL_PUB" -pubout -outform DER | \
  /opt/homebrew/opt/openssl@3/bin/openssl dgst -sha256 | /usr/bin/awk '{print $NF}')"

/bin/mkdir -m 0700 "$ABCR_AUTOQUAL_WORK"
/usr/bin/printf '%s\n' "$ABCR_AUTOQUAL_KEY_ID" | /usr/bin/grep -Eq '^[0-9a-f]{64}$'
"$ABCR_SEALED_RELEASE/env/bin/python" -I "$ABCR_AUTOQUAL_CLI" draft \
  --core "$ABCR_AUTOQUAL_CORE" --key-id "$ABCR_AUTOQUAL_KEY_ID" \
  --output "$ABCR_AUTOQUAL_DRAFT"
"$ABCR_SEALED_RELEASE/env/bin/python" -I "$ABCR_AUTOQUAL_CLI" attestation-core \
  --draft "$ABCR_AUTOQUAL_DRAFT" --output "$ABCR_AUTOQUAL_SIGNING_CORE"
```

把 `attestation-core.json` 送到**外部** signer。外部输出必须是标准 Ed25519
attestation，domain 精确为
`abcr.autonomous_qualification.bundle.v1`，并绑定同一个 `core_sha256`、key_id 和
issued_at。这里故意没有 `<本机 sign 命令>`；没有外部签名就是 `BLOCKED`。

收到 detached attestation 后：

```sh
"$ABCR_SEALED_RELEASE/env/bin/python" -I "$ABCR_AUTOQUAL_CLI" assemble \
  --draft "$ABCR_AUTOQUAL_DRAFT" --attestation "$ABCR_AUTOQUAL_ATTESTATION" \
  --output "$ABCR_AUTOQUAL_BUNDLE"

sudo /usr/sbin/chown root:wheel "$ABCR_AUTOQUAL_BUNDLE"
sudo /bin/chmod 0444 "$ABCR_AUTOQUAL_BUNDLE"
sudo "$ABCR_SEALED_RELEASE/env/bin/python" -I -B "$ABCR_AUTOQUAL_CLI" verify \
  --bundle "$ABCR_AUTOQUAL_BUNDLE" --release-id "$ABCR_RELEASE_ID" \
  --reviewed-commit "$ABCR_REVIEWED_COMMIT"
```

首次 registry 的 compare-and-swap 前置是 generation `0`、active `ABSENT`：

```sh
sudo "$ABCR_SEALED_RELEASE/env/bin/python" -I -B "$ABCR_AUTOQUAL_CLI" install \
  --bundle "$ABCR_AUTOQUAL_BUNDLE" --release-id "$ABCR_RELEASE_ID" \
  --reviewed-commit "$ABCR_REVIEWED_COMMIT" \
  --expected-generation 0 --expected-active ABSENT
sudo "$ABCR_SEALED_RELEASE/env/bin/python" -I -B "$ABCR_AUTOQUAL_CLI" doctor \
  --release-id "$ABCR_RELEASE_ID" --reviewed-commit "$ABCR_REVIEWED_COMMIT"
```

doctor 的准确成功口径是：

```text
subgate_status=PASS
fixture_only=false
autonomous_qual_overall=BLOCKED_EXTERNAL_DRILLS_REQUIRED
```

每次 mission-builder preflight 和每个 work item 都会重读 registry、检查 expiry/
revocation、重 hash adapter/runtime/Seatbelt/policy。安装后再次运行 8.6 的
mission-builder doctor；仍失败就停，不要把 config 中的 false 手改成 true。
mission-builder 在每个 preflight/work item 从 installer 固定的 canonical registry/key/
release/commit identity 动态复验，因此 genesis 后安装外签 registry **无需且禁止重跑
installer**。registry 缺失、过期、撤销或字节漂移会立即让 Codex 工程 mission 回到 deny。
它不会修改、启动或停止科学实验 dispatch supervisor；科学实验使用独立的 root-owned
experiment execution profile authority，二者不得互相借权。

registry 的后续 install/revoke/rollback 都必须读取 doctor 返回的当前 generation 与
active qualification id，再作为 `--expected-generation/--expected-active` 做 CAS。
不要猜数字。示例撤销：

```sh
sudo "$ABCR_SEALED_RELEASE/env/bin/python" -I -B "$ABCR_AUTOQUAL_CLI" revoke \
  --release-id "$ABCR_RELEASE_ID" --reviewed-commit "$ABCR_REVIEWED_COMMIT" \
  --qualification-id <exact-active-id> --reason '<明确原因>' \
  --expected-generation <doctor-current-generation> \
  --expected-active <doctor-current-active-id>
```

当前 candidate controller 的 status fixture 只资格化冻结命令边界，不是通用修复

### 9.4 独立科学实验 execution profile authority

**当前状态：`BLOCKED`；本轮禁止执行。本节没有可复制的安装命令。**

`qualify_abcr_experiment.py` 是未来 reviewed-runtime 的 fail-closed 骨架，不是当前 Mac 的
部署步骤。当前 sealed Python 没有受审并冻结的 `transformers`/`torch` 运行依赖，正式远端
CUDA adapter 也未资格化；因此现在运行 `prepare-profile`、`install` 或手工复制模型既不能

- 手写 execution profile、在 user-owned `$ABCR_BUILD_ROOT` 生成“root authority”，或把
  `local_rehearsal` 政名为 `formal_citable`；

这与日常 `带③L：否` 的分段快道无关：快道使用独立的本机 probe 边界，只能产出
“学习数据·不可引用”。控制面仍可接收目标、运行这一题快道验收、展示状态和收集反思；
正式科学 workflow 则诚实停在 `EXPERIMENT_EXECUTION.profile=BLOCKED`。

未来只有新的 exact reviewed release 同时满足以下外部输入，独立 verifier 才可发布一份
新的资格化 runbook：冻结且被签名覆盖的运行依赖、人工选定且全树 hash 的 Transformers
模型、root-owned 单链接工作目录、与实际硬件一致的 device/dtype、独立受审的远端 CUDA
adapter，以及 ticket 给出的“不超过 90 天”RFC3339 expiry。届时仍须由 sealed CLI 测量、

### 10.1 Human gateway 的安全重启

只有在 §8.5.1 已证明一次性发现器退出、最终 owner 已核对时才可重启。先保存
`launchctl print` 和 Human semantic doctor 输出；不要用 `kickstart -k` 掩盖退出原因。
计划内单服务重启的准确顺序是：

```sh
sudo /bin/launchctl print system/com.abcr.human-gateway
sudo /bin/launchctl bootout system/com.abcr.human-gateway
sudo /bin/launchctl bootstrap system \
  "$ABCR_LAUNCHD_ROOT/com.abcr.human-gateway.plist"
sudo /bin/launchctl print system/com.abcr.human-gateway
sudo -u abcr-human /usr/bin/env -i PATH=/usr/bin:/bin LC_ALL=C \
  ABCR_RELEASE_ID="$ABCR_RELEASE_ID" ABCR_ACTIVATION_STATE=ACTIVE \
  ABCR_SERVICE_LABEL=com.abcr.human-gateway PYTHONDONTWRITEBYTECODE=1 \
  PYTHONNOUSERSITE=1 PYTHONUTF8=1 "$ABCR_SEALED_RELEASE/env/bin/python" -I \
  -m abcr.control.human_gateway --doctor
```

最后一条必须 rc `0`/`ok:true`。随后由 owner 在原 p2p 私聊发送 `状态` 并收到新鲜
snapshot；旧 outbox 若有未送达回复也必须先按原 effect id 排空。仅仅“重启后又能回一条
新消息”不等于真实 Feishu redelivery/exactly-once drill 已 PASS；后者必须另留 event/outbox
证据，未做时继续 `BLOCKED`。

### 10.2 反向卸载已加载的九个 production job

若 8.5 中途失败或需要维护，按 bootstrap 的逆序逐个卸载；`print` 不存在才可跳过，
其他 bootout 错误必须停止调查。下面的 helper 只把“本来未加载”视为幂等成功：

```sh
abcr_bootout_if_loaded() {

    sudo /bin/launchctl bootout "system/$1"
  fi
}

abcr_bootout_if_loaded com.abcr.test-controller
abcr_bootout_if_loaded com.abcr.mission-builder
abcr_bootout_if_loaded com.abcr.auditor
abcr_bootout_if_loaded com.abcr.itempool
abcr_bootout_if_loaded com.abcr.probe-worker
abcr_bootout_if_loaded com.abcr.operator-reconciler
abcr_bootout_if_loaded com.abcr.human-gateway
```


### 10.3 Live 一题快道验收：这是“probe 可用”的最低证据

12 个 launcher structural doctor、11+1 semantic 矩阵和 Ollama `/api/version` 都不能单独
证明快道可用。只有 production owner 从真实飞书 p2p 触发，并完整穿过 Human → Operator →
root itempool → probe → 结果查看，才可把“`带③L：否` 快道”判为 live PASS。

owner 先发 `开始快道`，把机器人返回的完整 `PS-...` 填入下面第一行后原样发送：

```text
快道片段 PS-机器人刚返回的完整会话ID 1/1
预测：这条中性检查人格不会稳定提高一道开发题的得分
人格文本：请谨慎作答；不确定时明确说明，不要编造依据。
题量：1
种子：1
带③L：否
模型档：qwen25-7b-q4-v1
```

再发 `结束快道`。验收票据必须同时记录：同一个 session/request hash、唯一
`itempool_queued`、唯一 `probe_queued`、终态 `probe_completed`、`result_hash`、一条
`row_hash`，以及机器人给出的 `查看快道结果 PROBE-... 1` 能返回同一行。结果必须明确
`citable=false`/“学习数据·不可引用”，不得出现云实例创建/计费，也不得把 `带③L：否`
改写成 `是`。重复发送原 `结束快道` 必须复读同一对象而不产生第二个 probe。

任一阶段缺失、重复、超时、结果无法查看或只有离线 doctor 证据，都将
`LIVE_PILOT.segmented_fastlane` 保持 `BLOCKED`；不要写“真正可用”。
