## 0. 判定

**对楠的初步设想**：方向采纳，两处根本性修正。

方向正确的部分：人退到设计/反思/决策位、AI 承担日常运转、宏微观随时可观测、复用已验证部件而非另起炉灶——这四点与 2026 年自主研究系统文献的结论一致（该类系统最缺的恰是验证层、日志层和恢复层，而这三样 AILH 恰好久经实战）。

必须修正的两处：

**修正一：把监控对象从 AILH 换成实验体，不是换名，是换领域。** BOSS/监工体系的守护目标是"生产 agent 活着且诚实地干活"（在线率、诚实失败、自修改治理）；实验控制面的守护目标是"证据链有效"（溯源、防污染、盲评、预注册符合性）。杀死一个实验的通常不是崩溃——崩溃丢一天，能续跑；杀死实验的是静默的有效性破坏：跑错 split、配置漂移、judge 看到条件标签、选择性重跑。这些在 BOSS 的传感器视野里根本不存在。所以复用的应是部件与纪律，不是监控语义。

**修正二："BOSS 及时审阅消化实验结果并同步给人"这条通道，在确认期与你们自己的三条锁定纪律相撞。** ① v1.0 §6.2：holdout 冻结后楠不看单题、只看聚合与预定义错误类别；② V1.3 §8：禁"见显著即停"——若每天有一个 LLM 盯着效应方向讲故事给你听，等价于制造了非法的 sequential peeking 压力；③ AILH 自己的教训：AI 自评精度 11.5% 且方向错误，2026 文献同样把"夸大研究成功、缺乏严谨自评"列为 agentic 研究系统的首位缺陷。**修正为：过程事实（完成率、失败、成本、异常）随时同步不受限；探索期聚合图可日报；确认期效应方向只在预注册分析点解锁，之前任何角色（含 BOSS、含楠自己）不看。** BOSS 可以消化的是运行事实，不是科学结论。

**对既有建议文档**：整体采纳，一处内部矛盾修复，六处精化。

采纳：独立控制面而非改造 BOSS 全部自治逻辑；五层职责雏形；状态机思路；`protocol_hash + git_commit + config_hash + model_revision + split_hash + seed + manifest` 版本绑定；原始数据只增不改；"原文待审优于摘要"等三原则原样继承；shadow 先行；验收四条的精神。

矛盾修复：建议正文列了四层（实验体/监工/BOSS/人），原则句却是四个角色"船员/大副/验船师/船长"——**Auditor（验船师）在分工里缺位，而它恰是全案最重要的新增组件**。且建议把"读取原始结果重新评分、检查污染"塞给了监工——这违反楠自己确立的"不兼运动员与裁判"原则：产出结果的人不能验自己的结果。本设计将 Auditor 独立成第五组件（§7）。

六处精化：① 状态机拆成协议/批次/运行三层，run 级免批、批次级批信封、协议级逐项人批——否则探索期每天几十个 run 逐个 DRAFT→HUMAN_APPROVED，人被审批钉回日常循环，初衷全失（§3–4）；② "实验体 ABCR"应去拟人化——W1–W9 的 rig 是确定性批处理程序，不是 agent，agent 形态只在 W10 T1 出现且冻结（§2）；③ shadow 毕业改事件制而非"3 天"时间制（§10）；④ 补上建议完全没提的三样：云生命周期与预算熔断（对 ¥4000 硬顶而言这是财务上最重要的自动化，§6）、rig 自身正确性验证层（solo 研究者 + AI 写码的最大真实风险是 harness 本身错了，§7）、自动化建设的时间预算上限（防止 12 周研究被做成第二个治理工程，§10）；⑤ 每日同步内容规则化：例外驱动、逐数带 run_id 链接、确认期方向锁盲（§8）；⑥ 验收标准改为可测形式，含故障演练制（§11）。

## 1. 这套控制面在守什么（第一性起点）

按对项目的致命度排序，四类风险：

1. **有效性风险**（污染、盲评破坏、预注册违规、选择性报告、harness 自身错误）——不可逆，直接作废证据包；
2. **预算风险**（GPU 空转、失控批次）——¥4000 是物理边界，烧穿即无路可退；
3. **进度风险**（停摆、返工）——可逆但侵蚀 12 周窗口；
4. **便利风险**（人被打扰、操作繁琐）——最轻，但正是本次自动化的表面动机。

初步设想主要瞄准第 3、4 类；本设计把第 1、2 类升为主目标——因为 3、4 类靠 Claude Code 人机协作已能对付，1、2 类才是机器必须替人守夜的部分。

**十条设计原则**（理念层，供引导所有落地决策）：

- **P1 账本先于叙事**。全系统只有一个事实源（运行账本）；一切报告、面板、周报都是账本上的视图；无账本记录 = 未发生。这是对"AI 夸大汇报"的结构性免疫：Operator 说什么不算数，账本写了什么才算数。
- **P2 有效性重于在线率**。告警等级、审计强度、人工介入的优先序按 §1 的四类风险排，不按"系统卡没卡"排。
- **P3 确定性优先**。凡确定性代码能做的检查（哈希核对、重评分、manifest 对账、预算计量）绝不交给 LLM；LLM 只出现在协议规定的量表位置（judge）与叙事位置（计划草案、异常分诊摘要）。这是 11.5% 教训的直接推论。
- **P4 运动员 / 裁判 / 验船师三分**。生成（rig）、评分（scorer/judge）、验证（Auditor）是三个身份，权限物理隔离；judge 对条件标签盲。
- **P5 改动即新版本**。冻结对象（协议、split、阈值、held-out）只读；任何变更生成新版本号，旧版本不覆盖。技术拦截优先于流程约束（沙箱 deny，不是 prompt 叮嘱）。
- **P6 审批分层**。协议级逐项人批；计划级批"信封"；运行级零审批。人的签名花在改变证据性质的地方，不花在执行动作上。
- **P7 影子先行、事件毕业**。任何新自动化能力先以只提议不执行的方式运行，以"N 次零差异"而非天数毕业。
- **P8 预算即物理**。每个 run 预估计价、每个云实例登记于册、超信封拒绝入队、空转即告警。¥4000 与探索期 30% 是账本里的只读常量。
- **P9 报告 = 例外 + 链接**。同步给人的是偏差与待决事项，不是流水；每个数字可一跳到 run_id 原始证据（"原文待审优于摘要"在报告侧的应用）。
- **P10 人的注意力是最稀缺算力**。整个系统优化的不是"AI 做了多少"，而是"到达楠的信息质量"。告警有误报预算（§5），打扰本身是被验收的故障。

## 2. 总体架构

六个组件 + 一个事实源：

```
人类 PI（楠）
   │ 批协议 / 批信封 / 按确认期发射钮 / 终裁
   ▼
Governor（治理员，LLM 参与）          Auditor（验船师，确定性代码为主）
   计划草案·符合性预检·异常分诊·同步生成      重评分·manifest 对账·防污染检·健康面板·成本对账
   │ 派发（毕业后）                        ▲ 只读账本与工件
   ▼                                      │
Operator（操作员，Claude Code 常驻/会话）───┤
   建环境·入队·续跑·云生命周期·数据搬运       │
   │ 驱动                                 │
   ▼                                      │
rig（试验台，确定性批处理程序）─────────────┘
   读冻结配置 → 跑受试模型 → 写账本与工件
   ▼
受试模型（Qwen2.5 家族等）
```

命名修正：建议文档中的"实验体 ABCR"在本架构中拆成 **rig（试验台）+ 受试模型**。rig 不是 agent，没有目标、记忆或自主性，只把冻结配置翻译成前向传播和日志——防拟人化带来的自主蠕变。到 W10 T1，"受试系统"才升级为 AILH harness 冻结快照，但 rig 与账本仍在 ABCR 侧。

**单一事实源（运行账本）**：独立于 AILH mem0 的数据层，建议 Parquet + JSONL（原始事件）+ DuckDB（查询视图），五张核心表——

| 表 | 内容 | 写入者 |
|---|---|---|
| protocols | 协议/计划/split/阈值对象及版本、冻结状态、哈希 | 人（经 Governor 起草） |
| batches | 批次信封：预算、范围、状态 | Governor 起草 → 人批 → 系统更新状态 |
| runs | run 级 manifest（V1.3 §11 全字段 + 状态） | rig |
| steps | step 级记录（trajectory_id/step_id 原子行） | rig |
| costs / instances | 云实例登记、每 run 计价、对账 | Operator + Auditor |

事件流沿用 AILH 的 append-only + 哈希链 trace 写法（直接复用 trace_writer 模式）。

**权限矩阵**（技术强制，复用 Seatbelt 沙箱 deny 模式）：

| 目录/表 | rig | Operator | Governor | Auditor | 人 |
|---|---|---|---|---|---|
| protocols / splits / frozen（冻结区） | 只读 | 只读 | 只读（可提新版本草案到暂存区） | 只读 | 唯一写入者 |
| runs / steps / 原始输出 | 追加 | 只读 | 只读 | 只读 | 只读 |
| scores（评分产物） | — | 追加（跑评分器） | 只读 | 追加（复评结果） | 只读 |
| held-out 单题 | 按协议 | 禁读 | 禁读 | 仅聚合脚本 | 冻结后禁读 |
| 队列 / 云控制 | — | 读写 | 写（毕业后可派发） | — | 读写 |

## 3. 三层状态机

**协议对象**（协议文本、split、阈值、评价器版本、T1 冻结清单）：

`DRAFT → REVIEW → FROZEN →（修订走 AMENDMENT，生成新版本）→ SUPERSEDED`

FROZEN 后写路径被沙箱物理拦截；W3 预注册即协议对象整体转 FROZEN 的那次事件。

**批次对象**（一个被批准的实验计划信封）：

`DRAFT → APPROVED(信封生效) → DISPATCHING → SETTLED(全部 run 终态) → AUDITED → REPORTED`

**运行对象**：

`PLANNED → QUEUED → RUNNING → {PAUSED, FAILED} → COMPLETED → SCORED → AUDITED → {ACCEPTED, REJECTED, QUARANTINED}`；另设终态 `CANCELLED`。FAILED 可 RESUME 回 RUNNING（复用 resumable 思想）。

对比建议版的差异：① HUMAN_APPROVED 从 run 级上移到批次级（§4 详述）；② 增加 SCORED（评分是独立于运行的一遍）与 QUARANTINED（审计不过的批不删除、不采纳，隔离留证）；③ **所有非终态携带 TTL，每个看门狗周期做一次全局对账**（账本状态 vs 进程表 vs 云实例清单）——这是对"start 无 done 信号泄漏 715/1519 分钟"事故的通用化：任何长活状态若无对应的活体证据，超时即转异常并告警，绝不允许幽灵状态永久滞留。

## 4. 审批分层（本设计的关键机制）

"人退出日常循环"与"任何设计变更不得绕过人批"看似矛盾，解法是区分**改变证据性质的动作**与**执行动作**：

- **协议级（逐项人批，无例外）**：协议文本与修订、split 生成与变更、占位阈值定稿、评价器与 judge 更换、held-out 任何形式的访问、预注册内容、异常数据的排除决定、解盲。这一层继承"AILH 域无合并权限"的精神：Governor 只能起草进暂存区，生效签名永远在人。
- **计划级（批信封）**：Governor 每日/每批生成计划草案——任务族 × 臂 × 题量上限 × seed 集 × split 限定（仅 dev/calibration）× GPU 小时预算 × 截止时间。人批准的是这个信封。信封内，Operator 自由入队、重试、续跑、调整执行顺序，全程免批。信封外任何一维（多花一小时 GPU、多碰一个 split、加一个臂）都自动升协议级或新信封。
- **运行级（零审批）**：单个 run 的启停、失败重试、断点续跑、云实例的开关——账本留痕即可。

**确认期特例**：W4–W5 确认性批次全程只有个位数的"发射"动作，自动化其启动是负收益。确认期批次保留人按发射钮，系统只负责发射前核验（冻结对象哈希一致、split 正确、judge 盲评配置就位）并出示核验单。

## 5. 可观测性与告警

**进度心跳替代进程心跳**。继承 2026-07-06 的双 beat 教训（"判断环心跳不再冒充执行在岗"）并推进一步：实验域的"在岗"定义为**账本里 steps 的推进速率 vs 计划速率**。进程活着但 30 分钟零新 step = 停摆，与进程死了同级告警。这直接治"进程活着工作流停摆 7 天零告警"（G19/G51）这一类。

**三层钻取界面**（采纳建议的宏/中/微三层，压缩实现成本）：最小实现是账本上的三条 DuckDB 视图 + 一页静态 HTML/CLI 报表——宏观（本周假设推进、矩阵完成度、预算消耗、失败率、待审批队列）、中观（每 cell/臂的样本完成率与异常分布）、微观（单 run → 单题输出 → 激活摘要 → 配置 diff → stderr）。boss_console 的改造推迟到 W2 之后按需决定，W1–W2 不为界面花时间；"一分钟从全局钻到原始证据"靠视图与文件路径规范即可达成。

**告警三级 + 误报预算**：

- **A 级（即时，飞书 + 响铃）**：预算越界或实例空转、冻结对象被写企图、split hash 不匹配、judge 输入含条件标签、held-out 访问、安全事件。全部对应有效性与预算风险。
- **B 级（并入下次同步）**：失败率超阈、进度落后计划超 25%、审计复评不一致、parse 失败率超阈。
- **C 级（留控制台）**：其余一切。

误报预算：A+B 级合计每日 ≤3 条为健康线，连续超线即视为告警系统故障并降敏（继承 24h 按类冷却机制）。监测器无真实数据源时一律 dormant 弃权、不刹车（继承"误 HALT"修复的 fail-open-to-dormant 原则：告警必须基于阳性证据）。

**历史事故 → 机制映射**（既有建议点名了前三类，此处补全为可执行对照）：

| 已确证事故类 | 本设计对应机制 |
|---|---|
| 进程活着、工作流停摆（G19/G51） | 进度心跳（steps 速率）+ 全局对账 |
| 检测心跳冒充执行在岗 | 双 beat 继承；"在岗"唯一定义 = 账本 step 推进 |
| 源码与生效版本不一致 / 同名脚本两副本 | run 启动强制 git clean + code hash 入 manifest；单一规范路径，禁止副本；复用部署一致性校验脚本模式 |
| Worker 6 越权致数据污染 | 权限矩阵沙箱强制（非 prompt 约束）；Operator 无冻结区写权 |
| start 无 done 信号泄漏（715/1519 min） | 非终态 TTL + 周期性全局对账 |
| 误 HALT（无数据源即刹车） | 监测器无源则 dormant；告警需阳性证据 |

## 6. 云与预算控制

对 ¥4000 硬顶而言，这是全案财务价值最高的自动化，初步设想与既有建议均未覆盖。

- **实例注册表**：每个租用实例开机即在 costs/instances 表登记（供应商、规格、时价、关联批次）；下单当日核价（v1.0 纪律）录入。
- **生命周期五步固化**（继承 v1.0 §4.2 云纪律五条并机器化）：provision → 5% smoke test（不过即关机退出）→ run（checkpoint 常态化）→ 产物上传 + 哈希校验 → **完成即关机**。关机由 Operator 执行、由看门狗兜底核验。
- **空转告警（A 级）**：实例存活但无 RUNNING run 关联超过 15 分钟——这是最贵的一类泄漏。
- **计价对账**：每 run 按臂计价（对接 V1.3 三矩阵 E1/E2/E3 的逐张估算），Auditor 每批对账"预估 vs 实耗"，偏差纳入验收（§11）。
- **熔断常量**：总额 ¥4000、探索期 ≤30% 写入账本为只读常量；入队时预估超信封即拒绝，累计逼近熔断线（建议 85%）触发 A 级并冻结新批次入队，等人裁决。

## 7. Auditor（验船师）

定位：独立于 Operator 的验证组件，**以确定性代码为主体**；每个批次 SETTLED 后自动运行，产出审计报告，决定 ACCEPTED / QUARANTINED。judge 是评分量表的一部分（协议内的测量工具），不是审计员；审计员核验的是"测量过程是否按协议发生"。

每批六项固定清单：

1. **manifest 完整性**：计划 runs vs 实际；(item, seed, condition) 无缺漏无重复；缺漏表明示。
2. **重评分**：独立进程从原始输出重算全部确定性指标，与 scores 表比对；核心指标（exact match、规则判分）建议双实现或维护黄金用例集，对冲"审计器与 runner 共享同一 bug"的同源盲区。
3. **防污染检**：split hash 核对；抽取语料 ∩ 评测题 = ∅（哈希级）；judge 输入结构检查（不含条件字段）；prompt 内容 grep 泄漏词表。
4. **健康面板**：parse 失败率、拒答率、截断率、空输出率、退化重复度——任一超阈即整批 QUARANTINED（这是对"harness 自身错误"的批级兜底；单元级兜底在 rig 的黄金测试里，见 W1 方案）。
5. **版本一致**：git clean、code/config/template hash 与 manifest 一致、环境 lock 一致。
6. **成本对账**：见 §6。

QUARANTINED 批不删除、不采纳、不重跑覆盖——留证 + 人裁决，符合"负结果亦发布"的立场。

---

## 8. 同步节律与呈现纪律

采纳"上午计划与待审批 / 下午进展与偏差 / 晚间结果失败与明日建议 / 紧急仅 A 级"的四段框架，加三条内容规则：

1. **例外驱动**：正常推进只报一行汇总；篇幅留给偏差、失败与待决。
2. **逐数带链**：同步中每个数字附 run_id / batch_id，一跳可达原始证据；同步文本由 Governor 从账本视图生成，禁止自由回忆。
3. **方向锁盲**：探索期聚合图可入晚间同步；确认期（W4–W5）同步只含过程指标与"距预注册分析点还有 X"，效应方向在分析点整体解锁。这是 §0 修正二的落地。

周六自动出"周证据对象"包（一图 + 一段可复现说明 + 本周失败 + 下周假设），直接服务三轨复用与对外七件套——这一项让自动化直接产出楠的每周硬需求，而不只是省力。

## 10. 分阶段落地（与 12 周日历对齐）+ 建设预算

| 阶段 | 周 | 内容 | 自动化程度 |
|---|---|---|---|
| Phase 0 | W1 | 账本 schema + rig + manifest + 复评脚本（即 W1 方案本体） | 人经 Claude Code 手动操作全部环节 |
| Phase 1 | W2 | Operator 常驻能力（队列 / 续跑 / 看门狗 / 云生命周期）；Governor shadow（只出计划与偏差报告，人手动派发）；CLI 报表 | 执行自动、派发人工 |
| Phase 2 | W2 末–W3 | 事件制毕业（连续 20 个 run 经人工派发后 Governor 预检与实际零差异、Auditor 六项全绿）→ 探索批自动派发；四段同步接飞书 | 探索批全自动 |
| Phase 3 | W4–W5 | 确认期最严模式：冻结区只读、锁盲通道、人按发射钮、Auditor 全清单 | 执行自动、发射人工（by design） |
| Phase 4 | W10 | T1：AILH 快照作为受试系统接入，账本与审计仍在 ABCR 侧 | 轨迹级自动、协议冻结 |

**建设预算上限（本设计最重要的自我约束）**：W1 之后，控制面工程每周 ≤20% 工程时（约 5 小时），特性由实际痛点拉动、不由蓝图推动。**自动化永远不在关键路径上**：若某周自动化未就绪，实验照跑，人工派发是合法降级而非事故。这一条针对的是一个真实风险——AILH 的治理体系花了数周打磨，而 12 周研究日历吸收不了第二个治理工程；本次自动化的成败标准是研究进度，不是控制面完成度。

## 11. 验收标准（修订版）

1. 一个探索批（≥30 runs）从"信封批准"到"审计报告送达"零人工日常操作；
2. **故障演练制**：注入三类故障（杀 RUNNING 进程 / Operator 伪报完成但账本无 step / 尝试写冻结区），全部被发现、正确分类、恢复或拦截且留痕——比"任何异常可被发现"更可测；
3. 冻结对象的写路径被技术拦截（演练验证），而非仅流程禁止；
4. 宏观 → 任意单题原始输出的钻取 ≤1 分钟；
5. A+B 级告警日均 ≤3 条（防打扰是验收项，不是副作用）；
6. 成本对账偏差 <10%。

| 风险 | 信号 | 应对 |
|---|---|---|

## 13. 嵌入决策清单（可否决，未否决即按此执行）

- **D1** 审批三层制：协议级逐项人批 / 计划级批信封 / 运行级免批；替代 run 级逐个审批。
- **D2** Auditor 独立成第五组件，确定性代码为主体，与 Operator 权限物理分离；BOSS（Governor）不承担结果解读职能。
- **D3** 确认期效应方向只在预注册分析点解锁；日常同步限过程事实与探索期聚合。这是对初步设想"BOSS 消化结果日报"的最大修改。
- **D4** shadow 毕业采用事件制（20 runs 零差异 + Auditor 全绿），弃用"3 天"时间制。
- **D5** 数据层：Parquet + JSONL + DuckDB 独立账本；复用 trace 哈希链、feishu_send、沙箱 deny、审批令牌模式；不复用 judgment engine LLM 循环与 mem0 环。
- **D6** 控制面建设 W1 后每周 ≤20% 工程时；自动化不进关键路径，人工派发为合法降级。
- **D7** 云实例注册表 + 空转 >15min A 级告警 + 完成即关机核验，列为 P0 机制先于一切界面建设。
- **D8** 确认期批次"发射"永久保留人手，系统只做发射前核验。
